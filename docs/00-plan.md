# 专题总计划：Agent Engineering Handbook

> 最后更新：2026-09-07 ｜ 状态：M0 筹备

## 1. 一句话定位

**给已经会写代码的人，讲清楚怎么把 Claude Code / Codex 这类编码 Agent 用成生产力工具，而不是玩具。**

- 不是「AI 能干什么」的科普，是「我今天下午就能用上」的操作手册。
- 不做工具评测排行榜，做**跨工具通用的方法论** + 各工具的具体落地写法。
- 每一条技巧都要有：**为什么（机制）→ 怎么做（可复制的配置/命令）→ 什么时候别这么做（边界）**。

## 2. 目标读者

| 读者 | 他们的问题 | 我们给什么 |
| --- | --- | --- |
| 主力读者：有 1-5 年经验的工程师 | 「装了 Claude Code，但还是当补全用」 | 上下文管理、任务拆分、验证闭环 |
| 次要：技术 Leader | 「团队怎么统一用法、怎么评估收益」 | 仓库级配置规范、评审门禁、度量方法 |
| 次要：独立开发者 | 「怎么一个人干一个团队的活」 | 并行 Agent、自动化流水线 |

**明确不服务**：完全不写代码的用户、只想要 prompt 咒语合集的用户。

## 3. 内容支柱（5 个模块）

1. **心智模型** —— Agent 到底在循环什么；上下文窗口是预算不是容器。
2. **上下文工程** —— `CLAUDE.md` / `AGENTS.md`、记忆、检索、压缩、子 Agent 隔离。
3. **工作流** —— 计划模式、TDD 闭环、并行 worktree、代码评审、长任务续跑。
4. **扩展与集成** —— MCP、Hooks、Skills、自定义命令、CI 里的 Agent。
5. **工程治理** —— 权限与沙箱、成本控制、效果度量、失败模式与反模式。

详细篇目见 [`04-outline.md`](04-outline.md)。

## 4. 每篇文章的固定骨架

```
① 场景钩子（一个真实的痛点，30 秒内让人对号入座）
② 机制解释（配 1 张原理图 —— 这是本专题的差异化）
③ 操作步骤（可复制的配置 / 命令 / 目录结构）
④ 效果对比（before / after，最好有数据或截图）
⑤ 边界与反模式（什么时候不要用）
⑥ 延伸阅读（官方文档锚点链接）
```

**硬性要求：每篇至少 1 张原创图，且必须是「解释机制」的图，不是装饰图。**

## 5. 里程碑

| 阶段 | 目标 | 产出 | 完成标志 |
| --- | --- | --- | --- |
| **M0 筹备** | 立骨架 | 本仓库 5 份 docs + 模板 | 计划、资料源、配图规范三份文档定稿 |
| **M1 试产** | 验证流程 | 2 篇样板文（1 篇心智模型 + 1 篇实操） | 走通「写作 → 配图 → 导出 → 发布」全链路，沉淀出真正好用的模板 |
| **M2 主线** | 铺量 | 模块 1-3 共 14 篇 | 形成稳定周更节奏，图库风格统一 |
| **M3 深水区** | 立壁垒 | 模块 4-5 共 10 篇 + 配套示例仓库 | 有可运行的 demo 仓库配合文章 |
| **M4 成册** | 收敛 | 整理为在线手册（MkDocs Material / Docusaurus）+ PDF | 有目录、搜索、暗色模式的站点上线 |

**视频线（并行，从 M2 起）**：见 [`06-video-workflow.md`](06-video-workflow.md) 的 V0-V4 路线。
原则是**只做已发文章的派生**，不为视频单独选题。

**M0 → M1 之间必须停一下做复盘**：样板文写完后回头改模板，别带着坏模板铺 24 篇。

## 6. 节奏与工作流

- **周更 1 篇**，写作 4h + 配图 2h + 打磨 1h 是基线预算；超过 2 倍说明选题太大，拆。
- 每篇走同一条流水线：

```
选题卡 (Issue) → 提纲评审 → 初稿 (posts/<slug>/index.md)
   → 配图 (assets/diagrams/) → 自查 Checklist → PR → 合并 → 发布 → 回填数据
```

- 一个分支一篇文章，PR 描述里贴图片预览。
- 素材随手记：临时想法丢进 `docs/04-outline.md` 底部的「灵感池」，不单开文件。

## 7. 质量门禁（合并前逐项打勾）

- [ ] 所有「官方说法」都有链接，且链接可访问（见 `01-sources.md` 的引用规范）
- [ ] 所有命令/配置在真机上跑过一遍，版本号已标注
- [ ] 至少 1 张原创机制图，源文件已入库
- [ ] 图在**亮色和暗色**背景下都清晰
- [ ] 截图无敏感信息（token、路径含真实姓名、内部仓库名）
- [ ] 有「反模式 / 边界」章节，不是一边倒的吹捧
- [ ] 术语与 `03-writing-style.md` 的术语表一致
- [ ] 文章内所有相对链接可跳转

## 8. 度量

不追阅读量虚荣指标，看三个：

| 指标 | 怎么取 | 目标 |
| --- | --- | --- |
| **有效阅读**：读到底部的比例 | 统计脚本 / 平台数据 | > 35% |
| **可操作性**：读者反馈「照做成功了」 | 评论 / Issue / 私信计数 | 每篇 ≥ 3 条 |
| **复用度**：被引用、被转载、被同事翻出来看 | 反链 + 仓库 star 增量 | 专题结束 ≥ 500 star |

## 9. 发布渠道

- **主阵地**：本仓库（GitHub 上直接可读，Markdown + Mermaid 原生渲染）
- **同步**：个人博客 / 掘金 / 知乎专栏 / Medium（英文版择优翻译）
- **切片**：每篇提炼 1 张图 + 3 条要点，发 X / 小红书 引流回全文

## 10. 风险与对策

| 风险 | 对策 |
| --- | --- |
| **工具迭代太快，文章过期** | 每篇头部标注「适用版本 + 验证日期」；建立季度复检清单；机制类文章占比 ≥ 40%（机制比 UI 稳定） |
| 写成 changelog 搬运工 | 每篇必须有一手实验或踩坑，官方文档只做引用不做主体 |
| 配图拖慢进度 | 先用 Mermaid 出功能图，只有封面和核心机制图才上手绘/设计工具 |
| 选题同质化 | 定期扫 `01-sources.md` 的社区源，避开已被写烂的角度 |
| 单人产能不稳 | 保持 2 篇存稿缓冲；节奏保不住时降级为「短篇技巧卡」而非断更 |
