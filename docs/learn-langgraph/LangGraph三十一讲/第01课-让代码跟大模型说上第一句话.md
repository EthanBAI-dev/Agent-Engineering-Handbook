# 让代码跟大模型说上第一句话：消息和系统设定

> **导读：** 你平时是在网页上跟 AI 聊天，但要让它变成程序的一部分，得换个方式跟它说话。
> 这一讲把这件事拆开：一句话怎么送进去、回来的东西长什么样、
> 怎么用一句设定改变它的说话风格。读完你能自己写出跟大模型对话的代码，
> 并说清楚它为什么记不住你上一句说了什么。

环境已经装好了。现在的问题是：**代码怎么跟大模型说上话？**

大模型就是 ChatGPT、DeepSeek 那类会聊天的程序。你平时是打开网页、
在输入框里打字。但程序不会用网页，它得走另一条路。

## 先花两分钟把钥匙配好

要让代码调用大模型，你得先有一把钥匙——**就是一串字符，
用来证明这次是你在调用，好按你的账号算钱。**

所以从这一讲开始要花钱了，虽然很少：跑完这一整讲大概几分钱。

钥匙怎么申请、怎么设、怎么验证，全在 [课程总纲](../课程总纲/README.md)。
**设好之后确认这条命令能打印「有钥匙」再往下：**

```
python -c "import os; print('有钥匙' if os.environ.get('DEEPSEEK_API_KEY') else '没读到')"
```

## 全课只有这一行跟模型厂商有关

```python
from langchain_deepseek import ChatDeepSeek

model = ChatDeepSeek(model="deepseek-chat", temperature=0)
```

第一行是把客户端拿进来，第二行是造一个能说话的对象出来。

`temperature=0` 的意思是**让它尽量每次都给一样的回答**。这个值越大回话越发散，
调成 0 是为了让你跟着教程跑的时候，结果别每次都不一样。

**记住这一行的位置。** 后面三十讲，无论多复杂，跟模型厂商有关的就只有这里。
想换成别的模型，改这一行，别的一个字都不用动。

## 送一句话进去，看回来什么

最简单的用法是直接丢一个字符串：

```python
reply = model.invoke("用一句话说明什么是 Python 的列表。")
```

`invoke` 就是「送进去、等它回话」。这个词后面会反复出现——
**只要看到 `invoke`，就是「把东西交给它，然后拿回结果」。**

跑起来看：

```
python 课程代码/lessons/lesson01_talk_to_model.py
```

（待回填：运行后把实验一的真实输出换到这里）

**注意回来的不是一个字符串，是一个对象。** 它身上除了那句话，
还带着这次调用花了多少、用的是哪个模型这些信息。
要拿那句话，读它的 `content`。

## 字符串只是简写，真正送进去的是「消息」

上面那种写法能用，但它其实是个简写。完整的写法是这样：

```python
from langchain_core.messages import HumanMessage

reply = model.invoke([HumanMessage(content="用一句话说明什么是 Python 的列表。")])
```

**这里出现了这一讲最重要的概念：消息。**

一次对话是由一条条消息组成的。**每条消息都标着「这句话是谁说的」。** 有三种：

| 谁说的 | 用来干什么 |
| --- | --- |
| 人类消息 | 你说的话，也就是你的问题 |
| AI 消息 | 模型回的话 |
| 系统消息 | 你给它定的规矩，用户看不见 |

你直接丢字符串的时候，程序自动把它包成了一条「人类消息」。**所以两种写法结果一样。**

（待回填：运行后把实验二的真实输出换到这里，用来证明两种写法结果相同）

**为什么要知道这件事？** 因为从下一讲开始，程序里流动的就不再是一句话，
而是一串消息。你现在就得知道那串东西是什么。

## 加一条规矩，它的说话方式立刻变

系统消息是三种里最好用的。它不是问题，是**规矩**：

```python
from langchain_core.messages import SystemMessage, HumanMessage

reply = model.invoke([
    SystemMessage(content="你只能用不超过 15 个字回答，不许举例。"),
    HumanMessage(content="用一句话说明什么是 Python 的列表。"),
])
```

同一个问题，加了这条规矩，回来的东西完全不同：

（待回填：运行后把实验三的真实输出换到这里，与实验一的输出并排对比）

**所以呢？** 这意味着你不需要在每个问题前面都写一遍「请简短回答」。
**规矩只写一次，放在最前面，后面所有问题都受它管。**

后面每一讲，只要看到给模型定角色、定输出格式、定禁止事项，用的都是这一条。

## 它记不住你上一句说了什么

这一节是全讲最重要的部分。

先问它一句，让它记住你的名字。再单独问一次「我叫什么名字」：

（待回填：运行后把实验四的真实输出换到这里）

**它答不上来。**

这不是它笨，也不是钥匙的问题。**是因为你那两次调用，各是一次完全独立的对话。**
第二次调用送进去的东西里，压根没有第一次的内容。

**打个比方。** 每次调用都像去一家客服中心打电话。**你每次接通的都是一个新人，
他手上没有任何通话记录。** 你上次跟谁说了什么，他完全不知道。

**换句话说：模型天生不记事，它只看你这一次送进去的东西。**

### 那网页上的 AI 为什么记得住

因为网页帮你做了一件事：**每次你发言，它都把之前所有对话重新送了一遍。**

你可以自己验证——把前两句一起送进去：

```python
model.invoke([
    HumanMessage(content="我叫小白，记住我的名字。"),
    AIMessage(content=第一次它回的那句话),
    HumanMessage(content="我叫什么名字？"),
])
```

（待回填：运行后把实验五的真实输出换到这里）

**这次它答得出来了。**

所以所谓「AI 记得我」，从来不是模型记住了什么。
**是有人在每次提问时，把之前的记录重新交给了它一遍。**

**这句话你现在只需要记住，暂时不用管怎么做。** 但它会一路管到后面很多讲——
对话为什么会越来越长、为什么会撑爆、为什么关掉程序就全忘了，根子全在这里。

## 还有一样东西，现在只需要认个脸

除了聊天，后面还会用到一个能上网搜东西的工具。

它跟你平时用的搜索引擎不一样：**搜索引擎给你一堆链接让你自己点，
这种工具直接把找到的内容整理成文字返回**，好让程序接着用。

**现在不用申请它的钥匙**，也不用跑任何代码。等学到需要联网找资料的那几讲再回来配。
这里提一句，是让你以后看到它时不陌生。

## 两个会改变结果的细节

**第一，`temperature=0` 不等于每次完全一样。** 它只是让回话尽量稳定。
**同一段代码你跑两次，字句仍然可能有出入。** 这一讲里所有模型回的话，
你跑出来的都会和上面不完全相同——这是正常的，不是你哪里做错了。

**这一点后面要一直记着：程序怎么跑是确定的，模型回什么是不确定的。**

**第二，钥匙不要写进代码文件。** 用环境变量传给它。
写进代码的钥匙，会跟着代码一起被你传到网上。

## 这一讲得到了什么，下一讲接着讲什么

你能让代码跟大模型说上话了：**造一个模型对象，用 `invoke` 把消息送进去，
读回来的 `content`。** 消息分三种，其中系统消息只写一次就能管住后面所有问题。

更重要的是你知道了：**模型不记事。** 它只看这一次送进去的东西，
所谓的记忆全靠每次把历史重新送一遍。

但你现在能做的还只是一问一答：**你问一句，它答一句，然后就结束了。**

真正的活儿往往要拐弯——先看它答的是什么，再决定下一步做什么。
可你的代码里没有任何地方能表达「下一步该往哪走」。

下一讲就解决这件事：**怎么把「先做什么、什么情况下走哪条路」画成一张图，
交给程序按图执行。**
