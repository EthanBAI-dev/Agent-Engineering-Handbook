## 零、骨架从哪来

课程顺序**不是编的**，是官方课程 30 个 notebook 的原始顺序。
源仓库：`langchain-ai/langchain-academy`，Module 0–6。

**唯一的例外是第 05 讲**，它是编辑增补，源课程中没有。增补理由见下方第一节末尾，
且必须在正文中标明它是「先绕开框架」的一讲。除此之外不得再增删调序。

**执行顺序固定：** 读源 notebook 单元格顺序 → 写清承接／新内容／留给后课 →
标注段落去留 → 跑通源实验 → 成文 → 定稿后画图。

**不允许：** 先套「Why、心智模型、核心概念、FAQ、速查表」固定栏目再往里塞知识点；
靠关键词次数判断归属；为了让一讲「自足」而完整讲掉后面的课。

## 一、总体分段（层层递进的四个台阶）

| 台阶 | 讲次 | 读者在这一段获得的能力 | 交给下一段的问题 |
| --- | --- | --- | --- |
| **一、能跑起来** | 总纲 + 01–08 | 从零装好环境，写出一张会分叉的图，亲手写一遍循环，再让它长出工具和记忆，跑成服务 | 状态一多就乱，消息一长就炸 |
| **二、能管住状态** | 09–14 | 控制状态的形状、合并方式、进出边界，长对话不崩 | 全自动跑飞了，人插不进去 |
| **三、能让人插手** | 15–19 | 流式看见过程，中途停下、改状态、回到过去重来 | 一个 agent 干不完，要拆 |
| **四、能拆能上线** | 20–31 | 并行、子图、扇出、多角色协作、长期记忆、部署上线 | —— |

**时间连续性的写法**：每一讲的导读必须承接上一讲**真正留下的那个问题**，
结尾必须交出**一个具体的未解决问题**给下一讲。承接和交接都写在下表里，不许临场发挥。

### 为什么增补第 05 讲

框架的每一个特性，都是对某个具体痛点的回应。**读者没自己写过循环，就只能把
框架当黑箱背功能。** 第 05 讲让读者先用几十行代码手写一遍，撞上它的天花板，
第 06 讲再看框架版本时，才知道框架替他做了什么。

依赖关系决定了它只能放在这里：手写 agent 需要工具调用，而工具绑定在第 04 讲。

### 四条最容易踩的归属线

1. **存档器（07）≠ 长期存储（24）。** 前者是「一条会话的存档」，后者是「跨会话的记忆」。
   07 讲存档器时必须明说「跨会话的事在 24 讲」，但**不能提前讲长期存储怎么用**。
2. **`add_messages`（03）≠ 归并器完整机制（10）。**
   03 只说「它负责把新消息接到旧消息后面」，**不讲归并器是什么、怎么自定义**。
3. **手写循环（05）≠ 框架循环（06）。** 05 只写手写版并撞天花板，
   **不许给出框架解法**；06 不许把手写版再走一遍。
4. **本地服务（08）≠ 线上部署（28）。** 08 只到「在自己电脑上跑起来、能在浏览器里看图」。
