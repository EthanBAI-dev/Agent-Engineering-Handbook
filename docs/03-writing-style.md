# 写作规范

## 双版本制度

每篇文章出**两份**：

| 文件 | 面向 | 要求 |
| --- | --- | --- |
| `index.md` | **主版本**，写给完全没用过的人 | 见下面全部规则，能省则省 |
| `deep-dive.md` | 进阶版，写给想深挖的人 | 可以上密度、上英文原文、上机制细节 |

**主版本永远优先。** 想不清楚某段该放哪，就放进阶版。

## 语气（主版本）

**读者会边看边跳，没耐心，随时可能关掉。**
你的目标不是讲全，是让他**看完就能动手**。

- **一段最多 3 句。** 超过就分段。段与段之间必须空行。
- **一句话只说一件事。** 从句、括号补充、破折号插入语，全部拆开。
- **能不用术语就不用。** 非用不可时，先给例子，再给名词。
  - ❌「这叫验证闭环」 ✅「它自己跑测试、自己改，改到过为止」
- **正文不放英文原文。** 官方引用统一挪到文末，一句话带过。
- **用对话代替定义。**「你说：…… / 它做：……」比任何解释都好懂。
- **必须有一个生活化比喻。** 买菜、点外卖、带实习生——越日常越好。
- 主张要明确。「可能、也许、某种程度上」删掉。不确定就标注「未验证」。
- 不吹不黑。写清楚代价。
- 允许第一人称讲经历，但结论要能脱离个人经历成立。

### 四个自检问题

写完每一节问自己：
1. 一个从没用过这个工具的人，读到这里会卡住吗？
2. 这一节能用一句话概括吗？概括不了就拆。
3. 有没有哪个词我没解释就用了？
4. **这段能删吗？** 删了不影响动手的，就删。

## 结构（主版本）

**开头必须是「只看一句话的话」**——直接给可抄走的那一句，然后才展开。
很多人只会看这一段，这没关系，他也拿到东西了。

推荐顺序：

```
只看一句话的话      ← 直接给答案
你现在是怎么用的     ← 场景
然后你就开始返工了    ← 痛点，越具体越好
一直在检查的人是你    ← 点破
它为什么不自己检查    ← 原因，一句话
打个比方           ← 生活化类比
具体怎么写（三个例子）  ← 照抄就能用
填空模板           ← 不会写的兜底
特殊情况怎么办       ← 消除"我这儿不适用"的顾虑
另外几个小动作       ← 加分项
什么时候这招不管用    ← 边界，必须有
存下这张表就行       ← 速查
最后再说一遍        ← 一句话总结
```

其他硬要求：

- **单节 100-300 字**，一节只讲一个点。宁可 16 个小节，不要 6 个大段。
- **小标题写成人话或问句。**
  - ❌「验证闭环的构建」 ✅「它为什么不自己检查？」
- **表格只用于文末速查表。** 讲道理不许用表格——表格看着整齐，其实是在偷懒。
- 主版本 2000-3000 字（中文）。**宁短勿长。**
- 标题层级最多到 `###`。
- 代码块给的是**读者可以直接复制去用的话**，不是示意。
- 文末给一张**速查表**，两列：什么时候 / 你说什么。

## 什么时候可以写深

模块 4（扩展与集成）、模块 5（工程治理）面向的是已经用熟的人，可以提高密度。
但即使这两个模块，**每篇开头也要用一段大白话说清「这篇解决什么问题」**。

## 代码与命令

- 代码块必须标语言：` ```bash `、` ```json `、` ```markdown `。
- 命令给出**可直接粘贴运行**的完整形式，不要写 `<your-path>` 这类占位符而不说明。
- 配置文件片段标明文件路径：

  ````markdown
  `~/.claude/settings.json`

  ```json
  { "permissions": { "allow": ["Bash(npm run test:*)"] } }
  ```
  ````
- 涉及版本行为的，在文章顶部写明：

  ```markdown
  > 适用版本：Claude Code v2.x ｜ 验证日期：2026-09-07
  ```

## 术语表（全专题统一，不混用）

| 统一用法 | 不要用 | 说明 |
| --- | --- | --- |
| Agent | 智能体 / 代理 / AI 助手 | 保留英文，中文译名混乱 |
| 上下文窗口 | context / 记忆 | 指模型单次可见的 token 范围 |
| 上下文工程 | prompt 工程 | 两者不同，前者是本专题重点 |
| 工具调用（tool use） | 函数调用 | 与 MCP 术语对齐 |
| 子 Agent（subagent） | 子任务 | 特指独立上下文的执行单元 |
| Hooks | 钩子 | 保留英文，指 Claude Code 的 hooks 机制 |
| MCP Server | MCP 服务 | 保留英文全称首次出现时展开 |
| 提示词 | prompt / 咒语 | 中文正文里统一用「提示词」 |

## 排版细节

- 中英文之间加空格：`使用 Claude Code 时`。
- 数字与单位之间加空格：`200k tokens`、`4 小时`。
- 专有名词大小写照官方写法：`Claude Code`、`Codex`、`MCP`、`AGENTS.md`。
- 列表项句末不加句号（除非是完整多句）。

## 图与正文的关系

- 图前一句话引出，图后一句话点题，不要把图孤零零丢在段落之间。
- 图的结论必须在正文里用文字复述一遍（可访问性 + 搜索引擎）。
