# 写作规范

## 语气

- **对同行说话**，不对小白说话。不解释「什么是终端」。
- 主张要明确。「可能、也许、某种程度上」删掉，观点就是观点，不确定就标注「未验证」。
- 不吹不黑。写清楚工具的代价：token 成本、审查负担、失败模式。
- 允许第一人称讲经历，但结论要能脱离个人经历成立。

## 结构

- 文章长度 2000-4000 字（中文）。超过就拆成上下篇。
- 标题层级最多到 `###`。
- 每 3-5 段插入一个视觉锚点：小标题、图、代码块或表格。**不要出现连续 5 段纯文字。**
- 开头 3 句话内必须出现读者的痛点，不要先讲背景。

## 代码与命令

- 代码块必须标语言：` ```bash `、` ```json `、` ```markdown `。
- 命令给出**可直接粘贴运行**的完整形式，不要写 `<your-path>` 这类占位符而不说明。
- 配置文件片段标明文件路径：

  ````markdown
  `~/.claude/settings.json`

  ```json
  { "permissions": { "allow": ["Bash(npm run test:*)"] } }
  ```
  ````
- 涉及版本行为的，在文章顶部写明：

  ```markdown
  > 适用版本：Claude Code v2.x ｜ 验证日期：2026-09-07
  ```

## 术语表（全专题统一，不混用）

| 统一用法 | 不要用 | 说明 |
| --- | --- | --- |
| Agent | 智能体 / 代理 / AI 助手 | 保留英文，中文译名混乱 |
| 上下文窗口 | context / 记忆 | 指模型单次可见的 token 范围 |
| 上下文工程 | prompt 工程 | 两者不同，前者是本专题重点 |
| 工具调用（tool use） | 函数调用 | 与 MCP 术语对齐 |
| 子 Agent（subagent） | 子任务 | 特指独立上下文的执行单元 |
| Hooks | 钩子 | 保留英文，指 Claude Code 的 hooks 机制 |
| MCP Server | MCP 服务 | 保留英文全称首次出现时展开 |
| 提示词 | prompt / 咒语 | 中文正文里统一用「提示词」 |

## 排版细节

- 中英文之间加空格：`使用 Claude Code 时`。
- 数字与单位之间加空格：`200k tokens`、`4 小时`。
- 专有名词大小写照官方写法：`Claude Code`、`Codex`、`MCP`、`AGENTS.md`。
- 列表项句末不加句号（除非是完整多句）。

## 图与正文的关系

- 图前一句话引出，图后一句话点题，不要把图孤零零丢在段落之间。
- 图的结论必须在正文里用文字复述一遍（可访问性 + 搜索引擎）。
