# 发布前自查清单

复制到 PR 描述里逐项打勾。

## 可读性（小白文的硬指标）
- [ ] 找一个没用过这个工具的人试读，标出他卡住的地方
- [ ] 每个术语第一次出现都有大白话解释
- [ ] 没有一句话超过 40 字的长句 / 从句嵌套
- [ ] 小节数 ≥ 10，单节 ≤ 400 字
- [ ] 小标题是人话或问句，不是名词短语
- [ ] 关键小节有「> 小结」
- [ ] 有至少一个生活化比喻
- [ ] 文末有速查表和一句话总结
- [ ] 进阶内容有明确标注「新手可跳过」

## 内容
- [ ] 开头 3 句内出现具体痛点，没有冗长背景
- [ ] 有「机制」章节，解释了为什么，不只是怎么做
- [ ] 有「边界与反模式」章节
- [ ] 所有官方结论都有具体页面链接（非首页），并标注访问日期
- [ ] 个人经验结论已明确标注为「个人实测」
- [ ] 头部标注了适用版本与验证日期

## 可执行性
- [ ] 每条命令都在真机跑过
- [ ] 配置片段标明了文件路径
- [ ] 没有未说明的占位符
- [ ] 外部依赖标明了安装方式与版本

## 图
- [ ] 至少 1 张原创机制图（非装饰图）
- [ ] 源文件已入库（`.mmd` / `.excalidraw` / `.d2` / `.html` / `.tape`）
- [ ] 配色符合 `docs/02-visual-system.md` 的令牌，强调色 ≤ 3
- [ ] 亮色和暗色背景下都清晰
- [ ] 竖屏切片用的是**竖版专属图**，不是横图缩放（横图在手机上必然看不清）
- [ ] 每张图有描述性 `alt`
- [ ] 图的结论在正文中有文字复述
- [ ] 截图/GIF 无 token、无真实姓名路径、无内部仓库名

## 排版
- [ ] 中英文之间有空格
- [ ] 术语符合 `docs/03-writing-style.md` 的术语表
- [ ] 代码块都标了语言
- [ ] 无连续 5 段纯文字
- [ ] 所有相对链接可跳转

## 收尾
- [ ] 已更新 `docs/04-outline.md` 中该篇的状态
- [ ] 已想好 1 张切片图 + 3 条要点用于社媒分发
