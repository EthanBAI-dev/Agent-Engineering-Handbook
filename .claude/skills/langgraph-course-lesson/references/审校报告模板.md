# 审校报告模板（A 到 L）

按顺序输出，不得省略或调换。**报告只写在这里，不写进正式正文。**

---

## A. 本讲定位摘要

讲号、驱动问题、承接上一讲的哪个问题、交给下一讲的问题、源 notebook、
目标读者与背景、本讲拥有的概念。

脉络表没有明确的，写「假设：……」，**不要悄悄改变定位**。

## B. 评分表

按 `rubric.md` 的八个维度和权重打分。每行必须引用具体位置、说明读者影响、
给出具体修改动作。

表末给出加权总分，并单独重复维度 1、2、5 的分数与是否通过发布门槛。

## C. 分级问题清单

P0 / P1 / P2 / P3 分组列出。每条包含：位置、问题、
**为什么对「没写过代码的读者」是问题**、修改方案。

不确定的事实标记 `需要外部核验`。**版本相关的数字标记 `需本机实跑核验`。**

## D. 零基础读者模拟

逐段进行，按 `零基础规则.md` 第 4 节的七个问题回答。

输出一张表：段落 → 新概念 → 可能不认识的词 → 需要的前置知识 →
是否存在「用陌生词解释陌生词」→ 处理方式。

**明确指出读者最可能在哪一段关掉页面。**

## E. 标题与导读建议

标题给三组候选：问题式、场景式、结论式，每组 2 到 3 条。
选定一条并说明理由。**标题本身不得含未解释术语，且必须有主语和谓语。**

导读单独给一版，两到三句、60 到 120 字，
依次交代「现实问题 — 会经过哪些概念 — 读完能判断什么」。

## F. 源顺序对照表（仅供编辑使用）

左列是源 notebook 的单元格顺序，右列是本讲对应的小节。
逐项标出：保留 / 合并 / 拆分 / 补台阶 / 推迟到第几讲 / 删除，并给理由。

**不要把这张表写进正式文章。**

## G. 概念归属核对

对照 `参考资料/课程脉络与概念归属表.md`，列出：

- 本讲完整讲授了哪些概念（应与归属表的「完整讲授」列一致）
- 预告了哪些、回顾了哪些
- **有没有越界完整讲掉后面讲次的内容**

任何越界都是 P0。

## H. 实验与代码核对

- 脚本路径、是否需要钥匙、验收标准是否为确定值
- **正文里每个数字，逐个标出它在脚本输出的第几行**
- 找不到出处的数字，直接判维度 5 为 0，并列为 P0
- 脚本是否用 `[正文]` / `[脚本额外]` 标注

## I. 视觉方案

先审计现有配图是否仍匹配新结构，再提出增删。
每张图给出：对应知识点、插入位置、要证明的主张、数据来源、类型、
必须包含的元素、禁止出现的元素、图注、alt 文本。

**图注必须能被零基础读者读懂。**
按 `配图规则.md` 和 `数据图规则.md` 验收；发手机端的还要写出 360 px 下的布局与断行方案。

## J. 修改计划

保留 / 删除 / 新增 / 重排 / 简化 / 举例 / 核验 / 配图，
**每条都要对应 C 节的某个问题编号。**

## K. 修改前后对比

选 3 到 5 处最关键的改动，原文与改写并列，说明解决了哪个问题。
**必须包含导读和开头段的对比。**

## L. 术语与可读性审计

四张清单：

1. **保留的专业词**：词 → 为什么必须保留 → 首次出现时的原句（证明是「先解释后命名」）。
2. **删除的专业词**：词 → 用什么普通表达替代。
3. **后移的专业词**：词 → 移到本讲靠后位置还是后面第几讲 → 理由。
4. **仍然偏难的段落**：位置 → 难在哪里 → 是否接受该风险及原因。

最后附上机检输出摘要：

```bash
S=.claude/skills/langgraph-course-lesson/scripts
node $S/check-readability.mjs   <文件>
node $S/check-markdown-math.mjs <文件>
```

列出 ERROR 数、WARN 数，以及**每一条未修复 WARN 的保留理由**。

## M. 修订后评分与结论

独立重新打分，列出已解决、未解决、新引入的风险。

给出发布 / 不发布结论，并明确写出：

- 维度 1 是否达到 8 分门槛
- 维度 2、维度 5 是否达到 7 分门槛
- 机检 ERROR 是否清零
- 是否还有未解决的 P0

**没有在改稿中找到对应证据，不得提高分数。**
