# 配图规则

做图前必读。

## 一、图必须来自真实运行

**LangGraph 自带结构导出，图必须来自它，不许手画「大概是这样」。**

```python
print(graph.get_graph().draw_mermaid())
```

流程图一律以这个输出为准，再做视觉整理（换中文标签、加高亮、标注可选步骤）。
节点名、连线方向、虚线实线，**都不能跟真实输出对不上**。

## 二、三种版式

| 版式 | 画布 | 用途 | 何时做 |
| --- | --- | --- | --- |
| desktop | 880 px 宽 | 网页正文 | 内容未定稿时只做这一版 |
| mobile | 420 px 宽 | 手机阅读 | 正文定稿后补 |
| card | 912 × 1216 | 卡片分发 | 正文定稿后补，字号下限 32 px |

**内容没定稿就补 mobile 和 card 是浪费，一改全废。**

## 三、编码约定

- **连续量画曲线**（时间、步数、耗时、词元数）。
- **只有横轴是真正的离散类别时才用柱状图**（三种归并器、四种状态写法）。
- **系统结构、层级、归属、流程用图示**（方框＋箭头），不用柱状图。
- **精确对应关系用表格**，不要硬做成图。

## 四、颜色

| 语义 | 用途 |
| --- | --- |
| 主色 | 本讲新引入的节点或概念 |
| 灰 | 前面讲过、这里只是回顾的部分 |
| 强调色 | 出问题的地方、对比中变差的一侧 |

**同一概念在全课所有图里颜色一致。** 状态永远一个色，节点永远一个色。

## 五、图注

图注写**这张图证明了什么**，不写「如图所示」。

- ✗ 图 3：归并器对比
- ✓ 图 3：同一次运行，左边没写归并器只剩最后一条，右边攒齐了四条

## 六、ASCII 的唯一两个合法用途

**命令行**和**目录树**。其他一律 SVG。

理由可验证：360 px 屏幕只放得下约 40 个等宽半角字符；卡片版只吃图片；
可读性检查会跳过所有代码块，ASCII 里写错没人发现。

## 七、每讲至少一张的判据

**动手实验量出来的结果必须配图。** 那是最值钱的产出，只留文字太浪费。

一讲如果一张图都没有，先问：这一讲的实验产出了什么可看的东西？
答不上来，说明实验本身设计得不够。
