# 配图规则

做图前必读。本文件已合并窄屏版式规则，不再另开文件。
数据图（曲线、真实测量结果）另见 `数据图规则.md`。

---

## 一、图必须来自真实运行

**LangGraph 自带结构导出，图必须来自它，不许手画「大概是这样」。**

```python
print(graph.get_graph().draw_mermaid())
```

流程图一律以这个输出为准，再做视觉整理（换中文标签、加高亮、标注可选步骤）。
节点名、连线方向、虚线实线，**都不能跟真实输出对不上**。

## 二、哪一段该配什么

| 段落 | 该配什么 | 不要用 |
| --- | --- | --- |
| 前后对比 | 两栏对比图 | ASCII 箭头 |
| 结构说明 | 真正的流程图（方框＋箭头，标出哪一步可选） | ASCII 竖排箭头 |
| 核心概念 | **真实运行结果图**（脚本真跑出来的） | 凭空画的示意图 |
| 动手实验的每一步 | **实测结果图**，和脚本输出同源 | 只有文字 |
| 速查表 | Markdown 表格就够 | 图 |

### ASCII 的唯一两个合法用途

**命令行**和**目录树**。其他一律 SVG。三条理由都能验证：

- **手机上会横向溢出。** 360 px 屏幕大约只放得下 40 个等宽半角字符。
- **进不了卡片版。** 卡片只吃图片，ASCII 块在卡片里等于不存在。
- **机检管不到。** 可读性检查会跳过所有代码块，ASCII 里写错什么都没人发现。

## 三、三种版式，一份数据

| 版式 | 目录 | 画布 | 排布 | 最小字号 |
| --- | --- | --- | --- | --- |
| 电脑版 | `figures/desktop/` | 880 | 并排横排 | 11.5 |
| 手机版 | `figures/mobile/` | 420 | 竖向单列 | 13.5 |
| 卡片版 | `figures/card/` | 912，高 ≤ 900 | 横图 | **32** |

**前两版必须由同一段代码按参数输出，只有排布不同。分别手写两份，迟早对不上。**

**内容没定稿就补手机版和卡片版是浪费，一改全废。**

正文里用 `<picture>` 切换电脑／手机两版：

```html
<picture>
  <source media="(max-width: 640px)" srcset="figures/mobile/02-simple-graph.svg">
  <img src="figures/desktop/02-simple-graph.svg" alt="一张会分叉的流程图">
</picture>
```

## 四、窄屏：以缩到 360 px 宽为验收基准

**有效字号 = SVG 字号 × min(1, 360 / viewBox 宽度)**

- 正文标签有效字号不得小于 **12 px**；次要刻度不得小于 **11.5 px**。
- 单行中文尽量不超过 18 个字，超过就主动断行。
- 默认 360～420 单位宽的画布，优先竖向单列。
- 流程、比较、分类有三项及以上时上下堆叠，不要把三四张小卡横挤一行。
- 图内阅读顺序从上到下；箭头、编号和留白要让顺序不依赖宽屏。

### 窄屏重排不能删掉知识图形

**手机版的目标是重排，不是把图简化成纯文字卡片。**

凡是承担机制说明的箭头、位置关系、变化过程、前后对比，都要保留。

空间不足时的正确做法：**加画布高度 → 把横向关系改成纵向 → 文字换行 → 拆成两张图**。
**不要为了维持固定高度而删掉有解释作用的文字或图案。**

- 每张卡片尽量保留一个与知识点直接对应的小图形（节点用方框、岔路用分叉箭头、
  循环用回环箭头）。**只有装饰作用的通用图标不能代替机制图。**
- 遮住文字后图案就没意义了，说明这张图需要重新设计。
- 让知识图形成为视觉主体。左右分区时检查中间有没有无效空白，有就扩大图形区。
- **避免连续使用圆角胶囊、状态气泡包装每一句话**，那样很快就模板化。
  优先用大图、直接标注、细分隔线和空间关系。
- 说明文字不应比承载知识的结构或对比图更醒目。

### 桌面横表怎么转成手机版

**不要原样压缩。** 按「每一行变成一张纵向卡片」做语义转置：
行标题放卡片顶部，各列名变成彩色短标签，单元格说明完整保留。
**手机版与电脑版内容必须一一对应。**

## 五、卡片版为什么要单独做

卡片正文可用宽 912、可用高约 1130、图片默认高度上限 900。

- **必须用 SVG。** SVG 会被撑满 912，位图按原始尺寸显示。
- **宽高比必须 ≥ 1.01。** 竖图会先顶到 900 再等比缩小，两侧留一大片白。
- **字号下限是 32，不是 13.5。** 卡片在手机上按 390 px 显示，912 宽的图只渲染成
  329 px（缩放 0.361）；要达到 11.5 px 可读下限，卡片坐标系里就得有 32 px。

这条下限带来一个直接后果：**912 宽、32 px 字，一行只放得下约 24 个字，是电脑版的一半。**
所以卡片版必须：

1. **按「一卡一个要点」拆图。** 三面板对照图拆成三张卡，每张讲一件事。
2. **文案重写得更短。**
3. **用整宽横排，别用竖列。**

推荐高度取现成几档：513（16:9）、608（3:2）、684（4:3）、900（整页大图）。

## 六、颜色

| 语义 | 用途 |
| --- | --- |
| 主色 | 本讲新引入的节点或概念 |
| 灰 | 前面讲过、这里只是回顾的部分 |
| 强调色 | 出问题的地方、对比中变差的一侧 |

**同一概念在全课所有图里颜色一致。** 状态永远一个色，节点永远一个色。

**颜色跟着含义走，不按面板序号轮换。** 四张图讲同一种东西就用同一个颜色，
相邻要区分就用同色的深浅，不要换色相。
只有颜色代表**不同实体**时才用不同色相。

**颜色不能是唯一的区分手段。** 文字、形状或线型仍要能独立说明差异。

## 七、编码约定

- **连续量画曲线**（轮数、步数、耗时、字数、词元数）。
- **只有横轴是真正的离散类别时才用柱状图**（三种归并器、四种状态写法）。
- **系统结构、层级、归属、流程用图示**（方框＋箭头），不用柱状图。
- **精确对应关系用表格**，不要硬做成图。
- **公式不塞进图片**，除非公式本身就是这张图的知识点。

## 八、图注

图注写**这张图证明了什么**，不写「如图所示」，也不要把正文那句话再说一遍。

- ✗ 图 3：归并器对比
- ✓ 图 3：同一次运行，左边没写归并器只剩最后一条，右边攒齐了四条

好图注常见三种写法：

1. **指认**：「注意第 4 轮那一格——工具返回的一大坨全被原样带进了下一次请求。」
2. **对应**：「左图的虚线和右图的两个分支，指的是同一个岔路口。」
3. **交代来源**：「结构取自脚本运行时导出的真实图，节点名与代码里一字不差。」

## 九、系列课程的位置图

31 讲的系列可以在导读之后放一张紧凑的位置图，帮读者确认「这是第几讲、属于哪个台阶」。
它属于导航信息，**不是文章内部的分层脚手架**。

- 只显示总讲数、当前讲、台阶分组和当前台阶；不要重复整份大纲。
- **不使用「初级／进阶／专业层」这类标签**，也不告诉读者正文该读到哪一层。
- 电脑版可横向展示完整节点；手机版改为四台阶概览加组内进度，
  避免横向挤入三十多个小字标签。
- **当前讲不能只靠颜色表示**，还要写明讲号、标题和组内位置。
- 位置图应比正文知识图更矮、更轻。
- **全系列位置图由同一份课程清单生成**，改名或增删讲次时统一更新。

## 十、每讲至少一张的判据

**动手实验量出来的结果必须配图。** 那是最值钱的产出，只留文字太浪费。

一讲如果一张图都没有，先问：这一讲的实验产出了什么可看的东西？
答不上来，说明实验本身设计得不够。

## 十一、交付前的检查

- [ ] 结构图来自 `draw_mermaid()` 真实输出，不是手画的
- [ ] 出现数值的轴都有刻度和单位
- [ ] 颜色代表含义，不是面板序号；且不是唯一区分手段
- [ ] 电脑版和手机版都存在，且由同一段代码生成
- [ ] 图注指向图上的具体位置，没有复述正文
- [ ] ASCII 块只用于命令行和目录树
- [ ] 目视检查：无文字重叠、无裁切、无超出画布
- [ ] `node scripts/check-svg-mobile.mjs <目录>` ERROR 清零
- [ ] 要发卡片时，`node scripts/check-svg-card.mjs <目录>` 通过
