# LangGraph 课程写作 Skill

第一任务是**保住官方课程的教学脉络**，第二任务才是把它写成零基础、可运行、图文清楚的中文教程。

不要用统一模板重排源课程，不要靠写完后的关键词查重修补结构。

---

## 零、最高优先级：官方 notebook 决定课程骨架

写任何一讲之前，**必须先读对应的源 notebook**，按单元格顺序看：

```
langchain-ai/langchain-academy  →  module-N/xxx.ipynb
```

没有本地副本就先 clone。**不能只看自动提取的文本**——提取会丢掉单元格之间的依赖顺序、
输出与解释的对应关系。

`参考资料/原始素材大纲.md` 只用于检索关键词，**不能代替直接看源 notebook**。

### 唯一结构依据

```
docs/learn-langgraph/参考资料/课程脉络与概念归属表.md
```

**动笔前必读。** 批量改写时先读完整组源 notebook 并更新该表，再改任何一篇。

执行顺序固定：
**读源单元格顺序 → 写清承接／新内容／留给后课 → 标注段落去留 → 跑通源实验 → 成文 → 定稿后画图。**

### 不允许的做法

- 先套「Why、心智模型、核心概念、FAQ、速查表」等固定栏目，再把知识点塞进去。
- 只扫描术语出现次数，然后在文章之间搬运定义。
- 为了让一讲「自足」，把后面课程的内容完整讲掉。
- **自己发明大纲。** 顺序只能来自官方 notebook。

### 三条硬边界（最常被越过的）

1. **总纲只讲环境**，不讲状态、节点、边。
2. **02 讲不得引入存档器和 `add_messages`**；03 讲 `add_messages` 时只说它干什么，
   **归并器的完整机制归 10 讲**。
3. **05 讲手写循环，不许给出框架解法**；06 讲框架循环，不许把手写版再走一遍。
4. **07 讲的存档器是「单会话存档」，24 讲的长期存储是「跨会话记忆」**，
   07 只能说一句「跨会话在 24 讲」，不得提前展开。

**编号以脉络表为准。** 本节与脉络表冲突时，改本节，不改脉络表。

### 来源只留在内部，不写进读者正文

源 notebook、模块编号、官方课程名用于决定内部脉络与核对事实，
可以出现在任务卡、归属表、审校报告、代码注释和交接待办里，
**不得出现在文章标题、导读、正文、图内文字或图注中**。

- 不写「官方课程这样做」「按 notebook 顺序」「第几个单元格」「Module 4 里说」。
- 把这类句子改成直接讲知识或操作。
- 技术纠错直接写「常见错误是……」并给出正确做法，不向读者展示内部比对过程。
- 发布前扫描 `notebook|Notebook|单元格|模块 \d|Module|官方课程|源课程`，
  读者正文中的命中必须清零。**「延伸阅读」小节里的链接不算正文措辞。**

## 一、最高优先级：读者什么都不懂

**读者对这个领域一无所知。** 不是「懂一点」，是零。

他们没写过 Python，没用过命令行，不知道什么是状态机、回调、异步、装饰器、类型标注。
不知道什么是 agent、工具调用、上下文窗口、词元。
他们有普通高中的常识，读这篇是为了建立直觉，不是读文档。

**连续撞上几个陌生词，他们就关页面了。**

当准确和简单看起来冲突时，答案永远不是牺牲准确，而是**加一层**：
简单的说法在前，精确的说法在后。

**发布门槛：零基础读者理解度低于 8/10 就不发，总分再高也不发。**

完整的读者画像、术语准入、开头规则、读者模拟七问见 `references/零基础规则.md`——**动笔前读一遍**。
打分维度、权重与全部硬性门槛见 `references/rubric.md`。

## 二、写法硬规矩（优先级高于结构）

追求是**简单又明了**。做不到这一点，结构再完整也是废话。

### 1. 主语和谓语必须写出来

- ✗ 「状态在节点之间**流转**」——谁在流转？读者脑子里没有画面。
- ✓ 「**每个节点跑完，会把改动写回那份共享数据**，下一个节点读到的就是改完的。」

### 2. 动词要贴着主体，别把程序写成人

| ✗ | ✓ |
| --- | --- |
| 让 agent 自己思考下一步 | 程序把当前对话发给模型，模型回一个「要调哪个工具」 |
| 图会智能地选择路径 | 你写的那个函数返回哪个节点名，程序就跳到哪个节点 |
| 状态在图里传递 | 每个节点返回一个字典，程序把它合并进那份共享数据 |
| 节点消费状态 | 节点读取状态 |

**判据：一句话里如果程序「想」「知道」「理解」「决定」，改写成它实际做的动作。**
唯一例外是模型本身的输出，那可以说「模型判断」。

### 3. 每个数字后面必须跟一句「所以呢」

读者不会自动知道一个数字是大是小、是好是坏。

- ✗ 「递归上限默认是 10007 步。」
- ✓ 「递归上限默认是 10007 步。**也就是说，图真要是绕进死循环，
  它会一直转到一万多步才报错停下——你会先等到不耐烦，而不是马上看到错。
  调试时把它改成 5，几秒钟就能看出是不是绕进去了。**」

后果也要再推一步：「消息会丢」——丢了会怎样？
「模型看不到你上一句说了什么，它会像第一次见你一样重新问一遍。」

**判据：每出现一个数字、每出现一句「就会怎样」，都自问一次「所以呢？」。
答不出下一句，这句话就还没写完。**

### 4. 生活化的例子必须连回主体

举完比方要有一句把它接回来，否则读者只记住了流水线，没记住图：

> 传送带上的箱子谁都能往里放东西，但质检员只喊往左往右，不动箱子。
> **换句话说：改数据的是节点，决定走哪条路的是另一种函数，这两件事在这里是分开的。**

### 5. 导读要帮上理解，不是复述

标题下放**两到三句、约 60 到 120 个汉字**的导读，依次交代：
**现实问题是什么 — 会经过哪些核心概念 — 读完能判断什么**。

**判据：把导读盖住再读正文，理解成本有没有变高？** 没变高就是废话。

**导读必须承接上一讲真正留下的那个问题**（见脉络表「交给下一讲」列），不许临场发挥。
但**不能只写「接上一讲」**——读者可能没读过上一讲，那个问题要在这里重新说清楚。

导读只介绍内容，**不介绍文章的内部结构**。不写「本讲分三部分」这类阅读说明。

`scripts/check-readability.mjs` 会检查导读是否存在。

### 6. 标题也要有主语和谓语

术语不要顶在最前面。一个系列不要每篇都套同一个句式模子。

- ✗ 条件边与路由
- ✓ 怎么让程序在岔路口拐弯：条件边

## 三、术语准入

任何专业词进正文之前，五关全过：

1. 这段话**必须**用它才讲得通吗？不是就删。
2. 能不能**先说人话，后给学名**？
3. 能不能落到一个具体场景、动作或日常现象上？
4. 解释里**有没有引入新的没解释过的词**？有就重写解释。
5. 把这个词删掉，读者还能拿到核心意思吗？能就删。

引入顺序永远是：**具体场景 → 日常解释 → 专业名称 → 简单例子**。

硬约束：**绝不用没解释过的词去解释另一个词**；一段最多**一个**新的核心概念；
一段扛着三个以上陌生词就必须拆开或重写。

### 本课程的高危词清单

下列词**第一次出现时必须先给人话**，且只能在归属讲里展开：

| 词 | 先说的人话 | 归属讲 |
| --- | --- | --- |
| 状态 | 一份所有步骤都能看、都能改的共享数据 | 02 |
| 节点 | 一个普通函数，读这份数据，返回要改的部分 | 02 |
| 条件边 | 一个只负责回答「下一步去哪」的函数 | 02 |
| 归并器 | 一条规则，说明新旧两份数据怎么合成一份 | 10 |
| 存档器 | 每走一步就把当前数据存一份 | 07 |
| 线程 id | 一次对话的编号，换编号就是换一份记忆 | 07 |
| 中断 | 让程序停在半路等人回话，之后从原地继续 | 16 |
| 子图 | 把一整张图当成一个节点塞进另一张图 | 21 |
| 工具调用 | 模型不自己动手，它只回一句「请帮我调这个工具，参数是这些」 | 04 |

**英文 API 名（`StateGraph`、`add_messages` 等）可以出现，但必须紧跟一句中文解释它干什么。**

## 四、文章结构：沿源顺序自然生长，不强制段数

一讲通常只有下面这几块，**顺序以源 notebook 为准**：

1. **导读**：一个读者认识的现象，说清本讲承接上一讲的哪个问题。只有一行。
2. **讲解块**：按源 notebook 单元格顺序写。每块只讲一个新问题。
   「Why、心智模型」只在内容确实需要时用，不是固定栏目。
3. **动手实验**：用一个说明实验目标的 `##` 大标题。
   **不使用「Hello World」「动手做」这类标题。**
   实验和 `课程代码/lessons/lessonNN_*.py` 是同一件事，不是两份东西。
4. **必要的工程提醒**：只留会改变结果的边界、版本、默认值与复现参数。
5. **固定结尾**：统一使用 `## 这一讲得到了什么，下一讲接着讲什么`。
   标题固定，内容必须从本讲结果自然生长：先总结本讲真正得到的答案，
   再明确把哪个未解决问题交给下一讲（**必须和脉络表的「交给下一讲」一致**）。

FAQ、速查表、前后对照表、「加一层」都是**可选工具**。只是再说一遍正文就删掉。
**不要用「核心概念一、二、三」这种统一标题把源内容重新分类。**

### 两条仓库约定

- **环境准备只写在 `课程总纲/README.md`。** 单讲只留一句链接。
- **代码必须真跑过并留在仓库。** 正文里的数字必须能在脚本输出中找到。
  公用函数放 `课程代码/lgkit/`，单讲编排放 `课程代码/lessons/lessonNN_*.py`。
  脚本用 `[正文]` 和 `[脚本额外]` 注释区分主实验与参数扫描。
  **先让脚本跑通源实验，再把结果写进文章。**

## 五、配图：哪一段该配什么

**这是最容易整块丢掉的一部分。用 ASCII 顶替等于没配图。**

| 段落 | 该配什么 | 不要用 |
| --- | --- | --- |
| 前后对比 | 两栏对比图 | ASCII 箭头 |
| 结构说明 | 真正的流程图（方框＋箭头，标出哪一步可选） | ASCII 竖排箭头 |
| 核心概念 | **真实运行结果图**（脚本真跑出来的） | 凭空画的示意图 |
| 动手实验的每一步 | **实测结果图**，和脚本输出同源 | 只有文字 |
| 速查表 | Markdown 表格就够 | 图 |

**ASCII 块只允许两种用途：命令行和目录树。** 其他一律画成 SVG。三条理由：

- **手机上会横向溢出。** 360 px 屏幕大约只放得下 40 个等宽半角字符。
- **进不了卡片版。** 卡片只吃图片，ASCII 块在卡片里等于不存在。
- **机检管不到。** 可读性检查会跳过所有代码块，ASCII 里写错什么都没人发现。

**图的特殊便利：LangGraph 自带 `graph.get_graph().draw_mermaid()`，
能直接吐出这张图的真实结构。图必须来自它的真实输出，不许手画一个「大概是这样」的。**

配图细则见 `references/配图规则.md`。**做图前必读。**

## 五点五、跨课归属必须在动笔前确定

**规则：每个概念只有一讲完整讲授，别处只做理解当前内容所需的最短回顾。**

归属不能靠关键词次数判断，也不能在文章写完后再移动定义；
它必须来自源 notebook 的课程顺序。

完整归属表、允许的预告、实验边界见：

```
docs/learn-langgraph/参考资料/课程脉络与概念归属表.md
```

关键词检查器的「零错误」**不能证明文章跟着源课程走**，也识别不了换一种说法后的重复。

## 六、事实准确

简单不是含糊或说错的借口。

- **版本相关的数字一律以本机实跑为准，不引用记忆值。**
  （已有教训：递归上限记成 25，实测 1.2.11 是 10007。）
- 分清「某个库的默认值」和「普遍设计」。
- 分清「教学简化」和「硬性技术限制」。
- 分清框架行为和模型行为：图怎么跑是确定的，模型输出什么是不确定的。
  **凡是依赖模型输出的例子，必须说明「你跑出来可能不一样」。**
- 写清每段代码适用的版本区间。**LangChain / LangGraph 1.0 之后
  `langgraph.prebuilt` 已废弃，能力在 `langchain.agents`；不得给出 v0 写法。**
- 不把相关说成因果，不把某个任务上的经验说成定律。
- 类比要标明是类比，并在必要时说清它在哪里失效。

## 七、工作流

1. 批量任务先扫描整组源 notebook，建立／更新 `参考资料/课程脉络与概念归属表.md`；
   **单篇任务也必须读前后两讲的源 notebook。**
2. 直接看 `.ipynb` 单元格顺序，再用 `参考资料/原始素材大纲.md` 查关键词。
   不能只看自动提取文本。
3. **保留原稿。** 正式文章在 `docs/learn-langgraph/LangGraph三十一讲/`，
   旧稿在 `草稿/`。改写前先确认改的是哪一篇，**没有明确授权不要整篇覆盖**。
4. 按源顺序列文章骨架，逐项标出保留、移动、删除、补台阶、实验和配图。
   **先处理课程错位，再处理句子与术语。**
5. 先写并运行 `课程代码/lessons/lessonNN_*.py`，确认源实验跑通；
   再写正文中的代码、输出与解释。
6. 按源顺序成文。对照归属表，确认没有完整讲掉后面的内容。
7. 内容未定稿只做桌面版图；定稿后再补窄屏版。
8. **跑机检，ERROR 必须清零：**

   ```bash
   S=.claude/skills/langgraph-course-lesson/scripts
   node $S/check-readability.mjs   docs/learn-langgraph/LangGraph三十一讲/
   node $S/check-markdown-math.mjs docs/learn-langgraph/LangGraph三十一讲/
   node $S/check-svg-mobile.mjs    <图片目录>      # 有图时
   node $S/check-svg-card.mjs      <卡片图目录>    # 要发卡片时
   ```

   **WARN 不必清零，但每条都要给出保留理由。**
9. 扫描读者正文中的 `notebook|单元格|Module|官方课程|源课程`，命中必须清零。
10. 按 `references/rubric.md` 独立打分，列出仍未解决的风险。
    **维度 1 低于 8 分、维度 2 或 5 低于 7 分、有未解决 P0，都不得发布。**

**机器检查零错误只表示格式过关，不能证明课程顺序正确，也识别不了换个说法后的重复。**

## 九、通用课程开发规则

新建课程、批量重构、素材扫描、通用交接，遵循 `build-tutorial-course` 的规则。
本 skill 只补充 LangGraph 课程的零基础术语、事实准确、代码实验、配图和仓库约定。
