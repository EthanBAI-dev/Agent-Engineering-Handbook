# Agentic RAG：让它答「不知道」，比让它答得漂亮更难

> 本课结果：你能让答案带上可追溯的出处，并让检索落空时走一条模型碰不到的拒绝路径。

## 只看一句话的话

决定 RAG 能不能上线的不是答得好不好，是检索不到时会不会编。

> **术语说明**
>
> - **RAG（检索增强生成）**：先检索资料，再让模型只根据资料回答。
> - **引用（citation）**：答案里每个事实能追回具体哪一条资料。

流程谁都会画：检索 → 塞进提示词 → 让模型回答。难的是另外两件事。

## 引用的前提在检索之前

```python
CORPUS = [
    {"id": "doc-1", "source": "员工手册 v3 第 2 章", "text": "年假从入职满一年起算，每年 10 天。"},
    ...
]
```

每条资料**入库时**就带着 `id` 和 `source`。

这不是细节。如果知识库里只有正文，那么答案生成之后你无论如何也补不出出处——只能让模型猜一个，那就成了另一种编造。

实跑结果：

```text
问：报销期限是多久？
答：报销需在消费后 30 天内提交。
依据：['员工手册 v3 第 5 章']
  doc-2 · 员工手册 v3 第 5 章：报销需在消费后 30 天内提交。
```

引用不是在答案后面缀一句「来源：员工手册」，是**能定位到具体哪一条**。用户点进去要能看到原文。

## 拒绝要由条件边保证，不是提示词

```python
def route(state: State) -> str:
    return "answer" if len(state["hits"]) >= MIN_HITS else "refuse"
```

检索命中数不足，流程直接走向 `refuse` 节点。

实跑结果：

```text
问：公司几点下班？
答：知识库里没有找到相关内容，我不能回答这个问题。
依据：（无）
```

关键在于：**这条路径上模型根本没有被调用**。没有被调用，就没有机会编。

## 反面示范：把决定权交给模型

很多 RAG 实现是这样的——不管检索到没有，都把上下文交给模型，并在提示词里写「如果资料不足请说不知道」。

实跑结果：

```text
问：公司几点下班？
答：公司一般下午六点下班。
依据：（无）
```

语气笃定，没有出处，内容是编的。**用户没有任何办法分辨这一句和上一句的区别。**

第 06 课那条边界在这里第三次出现：提示词是建议，代码是约束。「不知道就说不知道」写在提示词里是劝阻，写成条件边才是阻止。

## 提示词还是要写

条件边挡住的是「一条资料都没有」。还有一种情况它挡不住：检索到了三条，但没一条真正回答了问题。

这时提示词里那句「只根据以下资料回答，不要补充资料之外的内容」仍然有用——它降低模型自由发挥的概率。

**两者是叠加关系，不是替代关系。**结构挡住能挡的，提示词降低剩下的概率。

## 检索质量决定上限

条件边只能判断「有没有命中」，判断不了「命中的对不对」。检索回来三条不相关的资料，Agent 会一本正经地基于错资料作答。

这一层的改进手段不在 LangGraph 里：切分粒度、向量模型、混合检索、重排。它们属于检索工程，本课不展开。

但有一条判断可以现在就用：**如果你的 RAG 答错了，先看检索回来的是什么**，再看模型怎么用它。绝大多数「模型不行」的抱怨，查下去是检索不行。

## 知识库会过期

员工手册从 v3 换成 v4，年假从 10 天改成 15 天。

如果旧文档还在库里，Agent 会同时检索到两个版本，然后给出一个笃定的错误答案，还带着看起来很正规的引用。

所以入库时除了 `source`，通常还要有版本和生效日期，检索时过滤掉失效的。**带引用的错误答案比不带引用的错误答案更危险**——它看起来是可信的。

## 互动实验：三个问题，三种结果

网页实验给你一个三条资料的知识库和三个问题：

```text
库里有的问题      →  答案 + 引用
库里没有的问题    →  拒绝回答
库里有但过期的    →  答案 + 引用，但内容是错的
```

通过条件：说出第三种为什么最危险，以及要在哪一步才能挡住它。

## 本课挑战：这个 RAG 哪里会出事

```python
def answer(state):
    context = "\n".join(h["text"] for h in state["hits"])     # 只拼正文
    reply = model.invoke(f"根据资料回答：{context}\n{state['question']}")
    return {"answer": reply.content, "citations": ["知识库"]}
```

两个问题：

1. `context` 里只有正文，没有 `id`。模型无法在答案中指出哪句话来自哪条资料，你也无法核对。
2. `citations` 写死成 `["知识库"]`——这是一个**看起来像引用的假引用**，比不给引用更糟，因为它让用户以为核对过了。

## 三个常见误区

### 「在提示词里写了『不知道就说不知道』就够了」

实跑的反面示范就是这么写的，模型照样编。结构上不给它机会才有效。

### 「检索回来越多越好」

无关资料会稀释相关资料，还会撞上第 14 课的上下文预算。命中数要有下限，也要有上限。

### 「RAG 答错了是模型的问题」

先看检索回来的是什么。绝大多数情况下，模型忠实地基于错资料回答了。

## 本课带走三句话

- 资料入库时就要带 id 和来源，事后补不出来
- 拒绝路径由条件边保证，让模型根本没机会编
- 带引用的错误答案比不带引用的更危险
