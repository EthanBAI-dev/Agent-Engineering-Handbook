# 项目：可信文件整理 Agent，跑通五条验收路径

> 本课结果：你交付一个 Agent，并用五条验收路径证明它在批准、拒绝、失败三种情况下都不会做错事。

## 只看一句话的话

这一课不引入任何新 API，只把前面的部件按正确顺序装起来，然后证明它可信。

> **术语说明｜验收路径**
> 一组固定的输入和预期结果。跑通它们才算完成，而不是「看起来能用」。

## 装配清单

```text
风险分级（16）  →  人工审批与改参数（17）  →  幂等副作用（19）
        全程 checkpointer（03 / 15），调用有上限（10）
```

一个都不能少，而且顺序不能换：

- 分级在最前面，否则禁止级操作也会走到审批那一步
- 幂等在最后面，因为它保护的是真正产生副作用的那一步
- checkpointer 贯穿全程，否则暂停和恢复都不成立

## 五条验收路径

验收标准不是「能跑」，是每条路径都符合预期。

### 1. 只读操作不打扰人

```text
扫描到 1 个超过 90 天的文件：['/tmp/a.log']
```

没有弹窗。`scan` 是 `auto` 级，直接执行。

如果这一条不通过——扫描也要审批——说明分级过严，人会在真正危险的操作到来之前就失去耐心。

### 2. 批准后执行，且只执行一次

```text
暂停：允许对 /tmp/a.log 执行 delete 吗？ → 人回答 'yes'
已delete /tmp/a.log

重复提交同一个 op_id：op_del_a 之前已执行过，跳过（幂等）
台账：{'op_del_a': 'delete'}
```

第二次提交同一个 `op_id`，操作被跳过。

这条路径模拟的是很现实的情况：用户点了两下按钮，或者网络重发了一次请求。没有幂等键的话，文件会被删两次——第二次可能删掉一个刚被重新创建的同名文件。

### 3. 拒绝后不产生任何副作用

```text
暂停：允许对 /tmp/keep.md 执行 delete 吗？ → 人回答 'no'
用户拒绝，未执行 delete
磁盘有没有变化：没有
```

注意最后一行：这是一条**断言**，不是一句描述。

拒绝路径最容易出的 bug 是「已经做了一半」——比如在询问之前就先做了备份、先改了状态、先发了一条通知。验收时必须真的去检查外部世界有没有变化，而不是只看返回值里写着「已取消」。

### 4. 中途失败，重试后恢复，且不重复执行

```text
暂停：允许对 /tmp/b.log 执行 archive 吗？ → 人回答 'yes'
已archive /tmp/b.log
台账里 op_arc_b 出现 1 次
```

这次运行中，副作用那一步失败了两次才成功。但台账里只有一条记录。

重试次数和最终记录数的关系，是判断幂等有没有做对的唯一硬指标。

### 5. 禁止级操作，连问都不问

```text
策略禁止：format_disk 不在允许清单内
```

没有弹窗。第 16 课那条原则在这里被验证：真正不该做的事，不给人犯错的机会。

## 这张图为什么可信

四条理由，每一条都对应一条验收路径：

1. **风险表是代码**，模型改不了它，未登记的操作按 `forbid` 处理
2. **危险操作前必然经过审批**，拒绝路径不碰任何副作用
3. **副作用那一步有幂等键**，重试和重复提交都只生效一次
4. **全程有 checkpointer**，失败可以从原地恢复，而不是从头再来

「可信」不是一个感觉，是这四条各自有一次实跑作证。

## 它仍然是教学版

必须说清楚边界，否则这一课会给人错误的信心：

| 教学版 | 生产版要换成什么 | 在哪一课 |
| --- | --- | --- |
| 台账在内存里 | 外部数据库，进程重启后还在 | 第 15 课 |
| 文件系统是模拟的 | 真实文件操作，需要路径校验 | 第 28 课 |
| 没有账号，谁都能审批 | 登录用户，且只能看自己的 thread | 第 29 课 |
| 没有记录谁批准了什么 | 审计日志 | 第 27 课 |
| 工具参数没有校验 | 参数白名单与路径限制 | 第 28 课 |

第三行尤其要注意。现在的审批界面对所有人开放——任何知道 `thread_id` 的人都能替别人点「同意」。第 03 课那条「`thread_id` 不是身份验证」，到这里已经是第五次出现了。

## 互动实验：给验收清单挑漏洞

网页实验给你这个 Agent 和一份**不完整**的验收清单（只有前两条）。你要找出它漏掉了什么。

```text
只测批准路径        →  漏掉「拒绝后不产生副作用」
只测成功路径        →  漏掉「失败后不重复执行」
只测已登记的工具    →  漏掉「未登记工具按 forbid 处理」
```

通过条件：补齐三条缺失的验收，并说出每一条能挡住哪一类线上事故。

## 本课挑战：给你的 Agent 写验收清单

拿你自己在做的任何一个 Agent，写出至少五条验收路径。每条包含：

```text
输入      ：固定的、可重复的
操作      ：包括人的回答
预期结果  ：状态里该有什么
外部断言  ：外部世界有没有发生变化
```

最后一栏最常被漏掉，也最重要。只检查返回值的验收，挡不住「说了没做」和「说没做却做了」这两类问题。

## 三个常见误区

### 「跑通了就是完成了」

跑通的通常只有批准路径。拒绝路径和失败路径才是事故的来源，而它们不会在正常使用中自己暴露。

### 「教学版和生产版差距不大，改改就能上」

差的是持久化、身份、审计和参数校验——四件事，四课。差距不在代码量，在这些东西缺失时你不会看到任何报错。

### 「有了人工审批就安全了」

审批只在人能做出正确判断时有效。第 16 课那条仍然成立：审批项太多，人会闭眼点同意；提示写得不清楚，人也判断不了。

## 本课带走三句话

- 装配顺序有意义：分级在前，幂等在后，checkpointer 贯穿全程
- 验收要包含拒绝路径和失败路径，并断言外部世界没有变化
- 「可信」不是感觉，是每条理由都有一次实跑作证
