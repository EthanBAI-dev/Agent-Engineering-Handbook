# 安全连接第一个模型 API：密钥放错地方，等于公开发布

> 本课结果：你能说出 API Key 该放在哪一层、为什么不能放进浏览器，并让缺少密钥的程序给出一句人能看懂的提示，而不是一段堆栈。

## 只看一句话的话

模型调用必须发生在服务端；浏览器只发问题、收答案，永远不碰密钥。

> **术语说明**
>
> - **API Key（接口密钥）**：证明程序有权使用某项服务，并把用量记到对应账户。
> - **服务端**：你自己的机器或服务器上运行的代码，用户看不到源码。
> - **客户端**：用户浏览器里运行的代码，任何人都能查看。

密钥不是「配置项」，它是账单和权限。放错一层，损失是真金白银。

## 先把危险说清楚

浏览器里的代码是公开的。打开开发者工具就能看到全部 JavaScript，包括你以为「压缩过看不懂」的字符串。

所以下面这两种做法都等于把密钥发布出去：

```text
1. 在前端代码里写 const KEY = "sk-ant-..."
2. 把密钥打进以 NEXT_PUBLIC_ 开头的环境变量
```

> **术语说明｜NEXT_PUBLIC_**
> Next.js 的约定：以它开头的环境变量会被打包进浏览器代码。它是「故意公开」的意思。

密钥泄漏之后，别人可以用你的账户额度，直到你发现并吊销。自动化扫描仓库的机器人，比你先发现的概率很高。

## 正确的分层

```text
浏览器           你的服务端                模型服务商
  │                  │                        │
  │── 问题 ────────▶ │                        │
  │                  │── 问题 + API Key ────▶ │
  │                  │◀──────── 回答 ──────── │
  │◀──── 回答 ────── │                        │
```

浏览器只知道你的接口地址。密钥只存在于中间那一层。

这一层在第 08 课会变成 `/api/agent`。这一课先把密钥本身安顿好。

> **配图 F07-1｜密钥只存在于中间那一层**
> **形式**：三层时序图 · `assets/lessons/07-key-layers.svg`
> **画什么**：浏览器 / 你的服务端 / 模型服务商三列。箭头依次是：问题 → 问题+API Key → 回答 → 回答。
> 在「浏览器」这一列画一把带叉的钥匙，在「服务端」画一把正常的钥匙。

> **替代文本**：浏览器只发问题收答案，API Key 只存在于你自己的服务端，浏览器永远不接触它。

## 密钥放在哪里

本地开发放在 `.env` 文件里，由程序在启动时读取：

```powershell
cp .env.example .env
```

然后把密钥填进去：

```text
ANTHROPIC_API_KEY=sk-ant-...
```

> **术语说明｜.env**
> 保存本地环境变量的文件。它属于「这台机器的配置」，不属于代码，因此不能进版本库。

关键的一步是确认它不会被提交。本仓库的 `.gitignore` 里有这一行：

```text
# 密钥不入库
.env
```

验证方法不是肉眼看，而是直接问 Git：

```powershell
git check-ignore -v lab/langgraph/.env
```

本仓库的实跑输出是：

```text
.gitignore:18:.env	lab/langgraph/.env
```

有输出，说明这个文件确实被忽略了。没有输出，说明它会被提交——立刻停下来修 `.gitignore`。

部署到 Vercel 时，同一个变量填在项目的环境变量设置里，不带 `NEXT_PUBLIC_` 前缀，它就只存在于服务端。

## 缺少密钥时，报错要像句人话

课程的统一模型入口做了一件小事，但它值得单独讲：

```python
def get_model(**kwargs):
    if not os.getenv("ANTHROPIC_API_KEY"):
        raise SystemExit(
            "没有 ANTHROPIC_API_KEY。\n"
            "  1) cp .env.example .env\n"
            "  2) 填进去 key\n"
            "  3) 重跑"
        )
    from langchain_anthropic import ChatAnthropic

    return ChatAnthropic(model="claude-sonnet-5", temperature=0, **kwargs)
```

在没有配置密钥的机器上运行，实跑输出是：

```text
没有 ANTHROPIC_API_KEY。
  1) cp .env.example .env
  2) 填进去 key
  3) 重跑
```

而不是一段几十行的调用栈。

> **术语说明｜SystemExit**
> 直接结束程序并打印一句说明，不产生调用栈。适合「配置不对」这类用户能自己修的问题。

这不是代码风格问题。初学者放弃的时刻，往往就是看到一段读不懂的报错的时刻。检查配置、给出下一步——两行代码，省掉一次放弃。

## 模型参数里唯一现在要管的一个

```python
ChatAnthropic(model="claude-sonnet-5", temperature=0)
```

> **术语说明｜temperature（采样温度）**
> 控制输出的随机程度。调低更稳定、更可复现；调高更多样。

课程统一用 `0`，因为教学需要可复现：同一个输入尽量得到同一个结果，你才能判断「这次不一样」是不是自己改坏了。

其余参数（最大长度、超时、重试）等真正遇到问题时再调，现在记住也用不上。

## 互动实验：密钥该放在哪一层

网页实验给出四个位置，你把密钥拖进去，立刻看到后果：

| 位置 | 结果 |
| --- | --- |
| 前端组件里的常量 | 任何访问者都能读到 |
| `NEXT_PUBLIC_` 开头的变量 | 被打包进浏览器代码，同样公开 |
| 服务端 `.env` + `.gitignore` | 安全，但只在你这台机器上有效 |
| 部署平台的环境变量设置 | 安全，线上正确做法 |

通过条件：把密钥放进后两个位置，并能说出前两个位置为什么等价——都会进入用户可以下载的那份代码。

## 本课挑战：三个检查项

在你第一次把密钥填进去之后，按顺序确认：

1. `git check-ignore -v <你的 .env 路径>` 有输出
2. 前端代码里搜不到 `sk-`、`API_KEY` 这类字符串
3. 部署平台的环境变量里，这个键名**没有** `NEXT_PUBLIC_` 前缀

三条都过，才算完成这一课。只跑通一次调用不算。

## 三个常见误区

### 「本地跑跑而已，不用管密钥」

本地和公开的距离，通常只有一次 `git push`。

密钥一旦进过某次提交，即使后来删掉，它仍然留在历史里。正确做法是从一开始就不让它进去。

### 「压缩混淆之后前端就看不见了」

压缩改变的是可读性，不是可见性。

浏览器必须拿到能执行的代码，字符串就一定在里面。搜索一下就能找到。

### 「用我自己的密钥先上线，以后再改」

「以后」通常意味着账单先到。

在没有第 10 课的调用限额之前，一个公开可访问的接口配上你的密钥，等于把额度开放给互联网。

## 本课带走三句话

- 模型调用只在服务端发生，浏览器永远不碰密钥
- `.env` 必须被 `.gitignore` 忽略，并且用 `git check-ignore` 验证过
- 缺少配置时给一句人能看懂的提示，不要甩一段堆栈
