LESSON 02 · 工具循环

模型
不会亲手算

Agent 工具调用的完整闭环

LESSON 022 / 8

它只是提了个申请

模型说「我要调用 add(2, 3)」，不等于它算出了 5。

它输出的是一段结构化的意图：函数名 + 参数。真正执行的是你的 Python 代码。

tool_calls: [{
  name: "add",
  args: {a: 2, b: 3}
}]
LESSON 023 / 8

决定和执行是两个节点

model 节点负责决定，ToolNode 负责执行。

分开的好处是出问题时你能一眼看出：是模型选错了工具，还是函数本身跑挂了。

分开才 debug 得动
LESSON 024 / 8

工具就是有说明书的函数

docstring 和类型标注就是模型看到的说明书。

写得含糊，模型就传错参数。这不是模型笨，是说明书没写清楚。

def add(a: int, b: int) -> int:
    """把两个整数相加"""
    return a + b
LESSON 025 / 8

bind_tools 只是递说明书

它把工具的名字、参数、说明交给模型，让模型知道有哪些牌可以出。

它不会让模型获得执行能力。执行永远发生在你的进程里。

LESSON 026 / 8

闭环的关键是 tools → model

工具结果必须回到决策者手上。

少了这条边，模型永远不知道自己调用的结果是什么——那就不是 Agent，是一次性调用。

这条边就是 ReAct
LESSON 027 / 8

易踩坑先手画，再用封装

create_react_agent 一行就能生成这套循环，很好用。

但先能自己画出这张图，之后用封装才不像在用魔法——出问题时你知道该拆哪一块。

LESSON 028 / 8

三句话带走

  1. model 生成工具调用意图
  2. ToolNode 执行真实函数并追加结果
  3. tools → model 闭合 ReAct 循环
