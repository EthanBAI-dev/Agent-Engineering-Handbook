# 术语解释样式对比

> 对比日期：2026-09-10
> 对比范围：`content/lessons/00–05`

## A 版：段后引用框

备份分支：`backup/00-05-quote-terminology-2026-09-10`
备份提交：`6c7563c`

```markdown
Agent 每走到一个 Node，就读取一次 State，写回一小块变化，再沿着 Edge 去下一站。

> **术语说明**
>
> - **State（运行状态）**：保存当前现场。
> - **Node（节点）**：完成流程中的一步工作。
> - **Edge（边）**：指定下一步路线。
```

特点：

- 扫读时容易找到解释。
- 术语与正文的视觉层级清楚。
- 连续出现时会制造较多提示框，文章容易被切碎。
- 更接近“正文 + 词典卡片”的阅读体验。

## B 版：同句或下一句直接解释

当前开发分支：`claude/ai-agent-tips-handbook-wcdgws`

```markdown
Agent 每走到一个 Node，就读取一次 State，写回一小块变化，再沿着 Edge 去下一站。

其中，State（运行状态）保存当前现场；Node（节点）完成流程中的一步工作；Edge（边）指定下一步路线。
```

特点：

- 阅读更连续，适合长篇教程。
- 解释紧跟第一次出现，不需要视线跳到提示框。
- 多个术语同段出现时句子会变长，需要后续人工润色。
- 更接近普通技术文章的阅读体验。

## 当前采用的规则

1. 每篇课程按独立页面处理，核心术语第一次出现时重新解释。
2. 格式统一为 `English（中文意思）`。
3. 在同一句或下一句说明它是做什么的。
4. 代码、函数名和命令保持原样，在代码块后解释。
5. 品牌、路径和文件名不强行翻译。
6. 网站仍可把解释做成虚线关键词的悬停/点击浮层；这不改变 Markdown 原稿的行内解释规则。
