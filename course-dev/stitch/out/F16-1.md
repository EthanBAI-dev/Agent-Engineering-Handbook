# F16-1｜三档风险，两条硬规则

- 课：第 16 课 · 审批策略：什么动作必须问人，什么动作根本不该给
- 形式：分级表图 · `assets/lessons/16-risk-tiers.svg`
- 目标文件：`assets/lessons/16-risk-tiers.svg`

## 路线 A（推荐）· 让能写代码的模型直接产出 SVG

把下面整段贴给 Claude / Codex：

```text
【任务】写一个 SVG，落到 apps/web/public/assets/lessons/16-risk-tiers.svg

【这张图在讲什么】
## 三个级别的实跑结果

    [read_file  ] 级别=auto    没有打断
                  → 直接执行 read_file(notes.md)

    [delete_file] 级别=approve  停下来问：允许执行 delete_file(/tmp/cache) 吗？
                  人回答 'yes'
                  → 经批准后执行 delete_file(/tmp/cache)

    [delete_file] 级别=approve  停下来问：允许执行 delete_file(/etc/passwd) 吗？
                  人回答 'no'
                  → 用户拒绝，未执行 delete_file

    [drop_table ] 级别=forbid  没有打断
                  → 策略禁止：drop_table 不在允许清单内，不会询问，也不会执行

注意第四条：`forbid` **不询问**。

这一点值得强调。如果禁止级操作也弹窗，就等于告诉用户「这件事点一下是可以做的」。真正不该做的事，不要给人犯错的机会。

【画什么】
三档横条 auto / approve / forbid，各配两三个典型动作。左侧一条竖轴标「后果可逆 → 不可接受」。 表外单画一个「未登记的工具」，用箭头直接指向 forbid。

【必须标注】
分级依据是后果不是感觉；未登记默认落到 forbid；forbid 档标「不询问」。

【不要出现】
把 forbid 画成一个弹窗——给用户一个不该存在的按钮，就是在等它被按下。

【替代文本（原样写进 <title> 与 <desc>）】
动作按后果分成自动、审批、禁止三档，未登记的工具默认按禁止处理且不询问。

【硬约束】
  - viewBox="0 0 720 H"，width="100%" height="auto"，不写固定 px 宽度
  - 颜色写成带兜底值的 CSS 变量：
      --ink #17231f  --muted #68736d  --card #fffdf7  --line #c9cfc7
      --lime #bafa4b（配 --on-lime #4d7100）  --green #355e48  --tertiary #9c432c
  - 圆角 rx="8"（小徽章 rx="2"）
  - 不用滤镜／渐变／blur；要立体感就用 2px 3px 的实心偏移矩形
  - font-family="var(--font-ui)"，正文 13px、标签 11px、标题 15px
  - 箭头用统一的 <marker>
  - 中文直接写在 <text> 里，不要转曲线

【自检】
  - 「必须标注」的每一条都能在 <text> 里找到
  - 「不要出现」的每一条确实没有出现
```
