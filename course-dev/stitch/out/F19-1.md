# F19-1｜重试把一次失败放大成三次扣款

- 课：第 19 课 · Retry 与幂等：重试很容易，重试不重复扣款才难
- 形式：对照时序图 · `assets/lessons/19-retry-side-effect.svg`
- 目标文件：`assets/lessons/19-retry-side-effect.svg`

## 路线 A（推荐）· 让能写代码的模型直接产出 SVG

把下面整段贴给 Claude / Codex：

```text
【任务】写一个 SVG，落到 apps/web/public/assets/lessons/19-retry-side-effect.svg

【这张图在讲什么】
## 幂等键：同一个 key 只生效一次

修法不在重试这一侧，在副作用这一侧：

    def charge_safe(state: State) -> dict:
        key = state["order_id"]                    # 幂等键：同一笔业务永远同一个 key
        if key in safe_ledger:
            return {"status": "已存在，直接返回上次结果"}
        safe_ledger[key] = "charged"
        ...

实跑结果：

    节点被调用 2 次，账本里只有 1 笔：{'o_4': 'charged'}
    最终状态：已存在，直接返回上次结果（第 2 次调用）

节点跑了两次，钱只扣了一次。第二次进来时它发现这个 key 已经处理过，直接返回上次的结果。

关键在于**幂等键必须来自业务，不能是随机生成的**。用 `uuid4()` 当 key，每次重试都会得到一个新 key，等于没做。正确的来源是订单号、请求 id、消息 id 这类「同一笔业务永远相同」的值。

【画什么】
上栏无幂等键——三次尝试，账本里三条记录，右侧标「图报告成功」； 下栏有幂等键——同样三次尝试，账本只有一条，第二三次命中「已存在，直接返回」。

【必须标注】
失败点画在「已扣款、未收到回执」之间；上栏账本三条标红。

【不要出现】
暗示 LangGraph 会自动去重。

【替代文本（原样写进 <title> 与 <desc>）】
没有幂等键时重试会重复产生副作用，加上幂等键后同一笔业务只生效一次。

【硬约束】
  - viewBox="0 0 720 H"，width="100%" height="auto"，不写固定 px 宽度
  - 颜色写成带兜底值的 CSS 变量：
      --ink #17231f  --muted #68736d  --card #fffdf7  --line #c9cfc7
      --lime #bafa4b（配 --on-lime #4d7100）  --green #355e48  --tertiary #9c432c
  - 圆角 rx="8"（小徽章 rx="2"）
  - 不用滤镜／渐变／blur；要立体感就用 2px 3px 的实心偏移矩形
  - font-family="var(--font-ui)"，正文 13px、标签 11px、标题 15px
  - 箭头用统一的 <marker>
  - 中文直接写在 <text> 里，不要转曲线

【自检】
  - 「必须标注」的每一条都能在 <text> 里找到
  - 「不要出现」的每一条确实没有出现
```
