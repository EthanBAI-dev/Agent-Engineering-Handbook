# F10-1｜预算判断必须在第一位

- 课：第 10 课 · 调用限额与成本：模型不会自己停，得你来停
- 形式：对照图 · `assets/lessons/10-route-order.svg`
- 目标文件：`assets/lessons/10-route-order.svg`

## 路线 A（推荐）· 让能写代码的模型直接产出 SVG

把下面整段贴给 Claude / Codex：

```text
【任务】写一个 SVG，落到 apps/web/public/assets/lessons/10-route-order.svg

【这张图在讲什么】
## 两条路径的实跑结果

上限设为 3 次。

**正常请求**：模型调一次工具，第二轮给出答案。

    模型调用 2 次，上限 3 次
    消息共 4 条
    最后一条：查到了，资料在官网。

没碰到上限，限额完全不影响正常使用——这是一个好限额的标志。

**失控请求**：模型每一轮都想再搜一次，永远不给最终回答。

    模型调用 3 次，上限 3 次
    消息共 7 条
    最后一条：已达本次请求上限（3 次模型调用），先返回目前的进展。

停在第 3 次，没有第 4 次，用户拿到一句说得通的话。

【画什么】
左右两栏画同一个条件边的两种写法。左栏先查预算再看 `tool_calls`，标「上限生效」； 右栏顺序反过来，第二个判断整块灰掉并标「死代码」。

【必须标注】
右栏那句「只要模型还想调用工具，预算检查永远轮不到」。

【不要出现】
把右栏画成会报错——它不报错，只会出现在账单上，这才是它危险的地方。

【替代文本（原样写进 <title> 与 <desc>）】
先查预算再看工具调用，上限才生效；顺序反过来，预算检查就成了永远执行不到的死代码。

【硬约束】
  - viewBox="0 0 720 H"，width="100%" height="auto"，不写固定 px 宽度
  - 颜色写成带兜底值的 CSS 变量：
      --ink #17231f  --muted #68736d  --card #fffdf7  --line #c9cfc7
      --lime #bafa4b（配 --on-lime #4d7100）  --green #355e48  --tertiary #9c432c
  - 圆角 rx="8"（小徽章 rx="2"）
  - 不用滤镜／渐变／blur；要立体感就用 2px 3px 的实心偏移矩形
  - font-family="var(--font-ui)"，正文 13px、标签 11px、标题 15px
  - 箭头用统一的 <marker>
  - 中文直接写在 <text> 里，不要转曲线

【自检】
  - 「必须标注」的每一条都能在 <text> 里找到
  - 「不要出现」的每一条确实没有出现
```
