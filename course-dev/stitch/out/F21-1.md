## 尽力而为：让分支自己兜住失败

    def source(state):
        try:
            ...
            return {"findings": [f"{name}：查到了"]}
        except ConnectionError as error:
            return {"findings": [f"{name}：查询失败（{error}）"]}

实跑结果：

    内部文档：查询失败（服务没响应）
    网页搜索：查到了
    综合 2 个来源得出结论

跑完了，但请注意最后那句提醒：**要让后面的节点知道有一条是失败的**。

如果 `summarize` 把「查询失败」当成一条正常资料去总结，用户会得到一个看起来完整、实际上缺了一块的答案——而且没有任何迹象表明缺了什么。失败的结果要带上可识别的标记，让下游能区分。

【画什么】
上下两条时间轴。上栏三个 0.3 秒的块首尾相接；下栏三个块上下对齐同时开始。 右端标出总耗时，两条轴用同一比例尺。

【必须标注】
两个实测耗时；扇入节点标「等所有分支完成」。

【不要出现】
把并行画成「更快完成每一步」——单步耗时没变，变的是总时长。

【替代文本（原样写进 <title> 与 <desc>）】
三个各 0.3 秒的查询串行需要 0.91 秒，并行只需要 0.31 秒。

【硬约束】

      --lime #bafa4b（配 --on-lime #4d7100）  --green #355e48  --tertiary #9c432c
  - 圆角 rx="8"（小徽章 rx="2"）
  - 不用滤镜／渐变／blur；要立体感就用 2px 3px 的实心偏移矩形
  - font-family="var(--font-ui)"，正文 13px、标签 11px、标题 15px

  - 中文直接写在 <text> 里，不要转曲线
