# F01-2｜循环不是能力，是一条边

- 课：第 01 课 · Agent（智能体）不是一次回答，而是一条会改变 State（运行状态）的路
- 形式：流程图 · `assets/lessons/01-conditional-edge.svg`
- 目标文件：`assets/lessons/01-conditional-edge.svg`

## 路线 A（推荐）· 让能写代码的模型直接产出 SVG

把下面整段贴给 Claude / Codex：

```text
【任务】写一个 SVG，落到 apps/web/public/assets/lessons/01-conditional-edge.svg

【这张图在讲什么】
## Edge：把节点连成执行路径

有了三个函数，它们还不会自己组成 Agent。

下面这些 Edge 才定义了执行顺序：

    graph.add_edge(START, "plan")
    graph.add_edge("plan", "work")
    graph.add_conditional_edges("work", should_continue, ["work", "review"])
    graph.add_edge("review", END)

把它画出来就是：

    START → plan → work ──条件成立──→ work
                      └──条件不成立──→ review → END

`START`（图入口）和 `END`（图出口）不是你写的业务函数。

`START` 标记流程从哪里开始；`END` 标记流程在哪里结束。

固定 Edge 只有一个明确下一站。条件 Edge 则先运行判断函数，再根据返回值选择路径。

【画什么】
`START → plan → work`，work 上方一条弧线绕回自己标「条件成立」， 另一条直线到 review 标「条件不成立」，再到 END。判断函数画成 work 与两条边之间的小菱形。

【必须标注】
两条分支各自的条件；判断发生在 **work 之后**，读的是更新后的 State。

【不要出现】
把判断画进 work 节点内部——那正是这一课要纠正的误解。

【替代文本（原样写进 <title> 与 <desc>）】
work 执行后由条件边判断，成立就回到 work 形成循环，不成立才走向 review。

【硬约束】
  - viewBox="0 0 720 H"，width="100%" height="auto"，不写固定 px 宽度
  - 颜色写成带兜底值的 CSS 变量：
      --ink #17231f  --muted #68736d  --card #fffdf7  --line #c9cfc7
      --lime #bafa4b（配 --on-lime #4d7100）  --green #355e48  --tertiary #9c432c
  - 圆角 rx="8"（小徽章 rx="2"）
  - 不用滤镜／渐变／blur；要立体感就用 2px 3px 的实心偏移矩形
  - font-family="var(--font-ui)"，正文 13px、标签 11px、标题 15px
  - 箭头用统一的 <marker>
  - 中文直接写在 <text> 里，不要转曲线

【自检】
  - 「必须标注」的每一条都能在 <text> 里找到
  - 「不要出现」的每一条确实没有出现
```
