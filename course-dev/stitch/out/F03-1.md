# F03-1｜checkpointer 存的是快照，不是聊天记录

- 课：第 03 课 · 同一个 thread（会话线程）为什么记得，换一个就忘了
- 形式：对照图 · `assets/lessons/03-checkpoint-vs-log.svg`
- 目标文件：`assets/lessons/03-checkpoint-vs-log.svg`

## 路线 A（推荐）· 让能写代码的模型直接产出 SVG

把下面整段贴给 Claude / Codex：

```text
【任务】写一个 SVG，落到 apps/web/public/assets/lessons/03-checkpoint-vs-log.svg

【这张图在讲什么】
checkpoint 可以理解为图在某一步的快照。

它记录的不只是最后一句聊天文本，还包括当时的 State，以及图继续运行需要的位置和元数据。

课程示例使用 `InMemorySaver`（内存检查点保存器）：

`InMemorySaver` 把 checkpoint 暂存在当前进程的内存中，适合无需数据库的教学实验。

    from langgraph.checkpoint.memory import InMemorySaver

再在编译图时传入：

    app = graph.compile(checkpointer=InMemorySaver())

代码中的 `compile`（编译图）会生成可以调用的应用 `app`。

`compile` 把节点、边和 checkpointer 组合成可运行的图。

从这一刻开始，图会在执行过程中保存 checkpoint。

图里的 model（模型节点）不需要为了“记忆”而重写：

model 读取当前消息并调用一次模型。

    def call_model(state: MessagesState) -> dict:
        return {"messages": [model.invoke(state["messages"])]}

这里使用了 `model.invoke`（调用模型方法）。

`model.invoke` 把当前 messages 发送给模型，并取得一条新的模型消息。

保存和恢复由图的运行层处理，节点继续只负责自己的工作。

【画什么】
左边一条「聊天记录」——只有几句文本；右边一个「checkpoint」——一个方框， 里面除了 messages，还有「下一步该跑哪个节点」和元数据。

【必须标注】
右侧那两项额外内容；一句「所以它能继续运行，而不只是能被读」。

【不要出现】
数据库表格图标——这一课的 InMemorySaver 只在内存里。

【替代文本（原样写进 <title> 与 <desc>）】
checkpoint 不只保存对话文本，还保存当时的完整状态和继续运行所需的位置信息。

【硬约束】
  - viewBox="0 0 720 H"，width="100%" height="auto"，不写固定 px 宽度
  - 颜色写成带兜底值的 CSS 变量：
      --ink #17231f  --muted #68736d  --card #fffdf7  --line #c9cfc7
      --lime #bafa4b（配 --on-lime #4d7100）  --green #355e48  --tertiary #9c432c
  - 圆角 rx="8"（小徽章 rx="2"）
  - 不用滤镜／渐变／blur；要立体感就用 2px 3px 的实心偏移矩形
  - font-family="var(--font-ui)"，正文 13px、标签 11px、标题 15px
  - 箭头用统一的 <marker>
  - 中文直接写在 <text> 里，不要转曲线

【自检】
  - 「必须标注」的每一条都能在 <text> 里找到
  - 「不要出现」的每一条确实没有出现
```
