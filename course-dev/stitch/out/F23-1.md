# F23-1｜共享累加字段会被计两次

- 课：第 23 课 · Subgraph：封装很简单，State 对接才是坑
- 形式：对照图 · `assets/lessons/23-shared-field-trap.svg`
- 目标文件：`assets/lessons/23-shared-field-trap.svg`

## 路线 A（推荐）· 让能写代码的模型直接产出 SVG

把下面整段贴给 Claude / Codex：

```text
【任务】写一个 SVG，落到 apps/web/public/assets/lessons/23-shared-field-trap.svg

【这张图在讲什么】
## 子图能单独跑、单独测

    solo = approval_graph.compile(checkpointer=InMemorySaver())

实跑结果：

    只跑子图：approved=True sub_audit=['提出申请：单独测试', '人工批准']

**这是抽子图最实在的好处。**审批逻辑可以脱离业务流程单独验收——第 20 课那五条验收路径，现在可以只针对审批子图写一遍，业务流程改了也不用重跑。

【画什么】
上栏父子共享 `audit`——子图把看到的完整值写回，父图 reducer 再累加一次， 结果里「父图做了一件事」出现两次并标红；下栏子图改用自己的字段名，两条轨迹各自干净。

【必须标注】
触发条件是「在 schema 里声明」，与子图写不写、与 interrupt 都无关。

【不要出现】
把它画成 LangGraph 的 bug——这是共享字段合并语义的自然结果。

【替代文本（原样写进 <title> 与 <desc>）】
父子图共享带 reducer 的字段时，父图已有的值会被回写并再累加一次，改用不同字段名可避免。

【硬约束】
  - viewBox="0 0 720 H"，width="100%" height="auto"，不写固定 px 宽度
  - 颜色写成带兜底值的 CSS 变量：
      --ink #17231f  --muted #68736d  --card #fffdf7  --line #c9cfc7
      --lime #bafa4b（配 --on-lime #4d7100）  --green #355e48  --tertiary #9c432c
  - 圆角 rx="8"（小徽章 rx="2"）
  - 不用滤镜／渐变／blur；要立体感就用 2px 3px 的实心偏移矩形
  - font-family="var(--font-ui)"，正文 13px、标签 11px、标题 15px
  - 箭头用统一的 <marker>
  - 中文直接写在 <text> 里，不要转曲线

【自检】
  - 「必须标注」的每一条都能在 <text> 里找到
  - 「不要出现」的每一条确实没有出现
```
