```text
## 组合使用才是真实界面的样子

`stream_mode` 可以传一个列表，事件会带上自己属于哪一种：

    for mode, event in app.stream(payload, stream_mode=["updates", "messages"]):
        ...

实跑输出（截取）：

    ▸ 进度：model 执行完毕
      · 正文块 '北京：晴，24 度'
    ▸ 进度：tools 执行完毕
      · 正文块 '北'
      · 正文块 '京'
      ...
    ▸ 进度：model 执行完毕

真实界面通常就是这个组合：`updates` 驱动上方的状态条，`messages`（过滤后）驱动下方逐字出现的回答。

顺带注意一个反直觉的地方：进度里 model 出现了两次。第一次它没写正文，只提出了工具调用——这正是第 02 课的结论，界面上不该把这一次显示成「正在回答」。

【画什么】
同一次运行，三列并排。`updates` 列三个节点事件；`values` 列四次状态快照（含第 0 次）； `messages` 列一串文本块，其中来自 ToolMessage 的那几块标红。

【必须标注】
`values` 的第 0 次是「图还没跑就给了初始状态」；`messages` 列标红处标「这是工具结果，不该给用户」。

【不要出现】
把三种模式画成递进关系——它们是不同粒度，不是不同阶段。

【替代文本（原样写进 <title> 与 <desc>）】
updates 给节点事件，values 给完整状态快照，messages 给逐字文本但混有工具结果。

【硬约束】
  - viewBox="0 0 720 H"，width="100%" height="auto"，不写固定 px 宽度
  - 颜色写成带兜底值的 CSS 变量：
      --ink #17231f  --muted #68736d  --card #fffdf7  --line #c9cfc7
      --lime #bafa4b（配 --on-lime #4d7100）  --green #355e48  --tertiary #9c432c
  - 圆角 rx="8"（小徽章 rx="2"）
  - 不用滤镜／渐变／blur；要立体感就用 2px 3px 的实心偏移矩形
  - font-family="var(--font-ui)"，正文 13px、标签 11px、标题 15px
  - 箭头用统一的 <marker>
  - 中文直接写在 <text> 里，不要转曲线

【自检】
  - 「必须标注」的每一条都能在 <text> 里找到
  - 「不要出现」的每一条确实没有出现
```
