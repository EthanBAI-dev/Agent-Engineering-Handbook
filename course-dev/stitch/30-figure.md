# 模板 C · 配图（37 张）—— 先看这一段再决定用不用 Stitch

## 建议：37 张里大部分不要交给 Stitch

课程里每一张配图的规格都写死了 **必须标注** 的中文文字（「劝阻／阻止／兜底」「箭头停在中层」…）。
这决定了工具选择：

| 图的类型 | 张数（约） | 推荐做法 | 为什么 |
| --- | --- | --- | --- |
| 流程图 / 状态图 / 对照图 / 分层图 | 30 | **直接生成 SVG 代码** | 文字精确、颜色直接用站点变量、能进 git diff、改一个字不用重画 |
| 界面示意（长得像产品截图的） | 5 | **Stitch** | 这本来就是 UI，Stitch 的强项 |
| 概念隐喻插画 | 2 | 图像模型（Nano Banana / Imagen） | 不含必须精确的文字 |

**图像模型画中文字几乎必错**（缺笔画、错字、糊）。而 37 张里有 35 张的规格都要求精确标注。
所以默认路线是 SVG 代码生成，不是画图。

SVG 的另一个好处：可以直接用站点的 CSS 变量，深浅色和主题跟着站点走，
而 PNG 得为每种情况各导一次。

---

## 路线 1（推荐）· 生成 SVG 代码

把 `out/` 里对应的 `F{{课号}}-{{序号}}.md` 整个贴给任意能写代码的模型（Claude / Codex 都行），
它已经包含了规格全文和下面这段约束：

```text
【任务】写一个 SVG，落到 apps/web/public/{{目标路径}}

【硬约束】
  - viewBox="0 0 720 {{高度}}"，width="100%" height="auto"，不写固定 px 宽度
  - 颜色只用这些，写成 CSS 变量并给出兜底值，例如 fill="var(--ink, #17231f)"
      墨色 --ink #17231f      次要 --muted #68736d
      卡片 --card #fffdf7     描边 --line #c9cfc7
      强调 --lime #bafa4b（配 --on-lime #4d7100）
      深绿 --green #355e48    警示 --tertiary #9c432c
  - 圆角一律 rx="8"（小徽章 rx="2"）
  - 不用滤镜、不用渐变、不用 blur；需要立体感就用 2px 3px 的实心偏移矩形
  - 文字用 font-family="var(--font-ui)"，正文 13px，标签 11px，标题 15px
  - 箭头用一个统一的 <marker>，不要每条线各画一个三角
  - 必须内嵌 <title> 和 <desc>，内容用规格里的「替代文本」原文
  - 中文文字直接写在 <text> 里，不要转曲线
【自检】
  - 规格里「必须标注」的每一条，都能在 SVG 的 <text> 里找到
  - 规格里「不要出现」的每一条，都确实没有出现
```

{{规格里的「必须标注」原文，逐条列}}

{{规格里的「不要出现」原文，逐条列}}

## 完成一张之后

1. 文件放到 `apps/web/public/assets/lessons/`，文件名用规格里给的那个。
2. 在课程正文对应位置换成图片组件，`alt` 用规格里的「替代文本」**原文**。
3. 把 `content/lessons/*.md` 里那个配图区块的 `**形式**` 行改成 `**状态**：已完成 · <路径>`，
   然后重跑 `python3 course-dev/scripts/build-figure-index.py`。
