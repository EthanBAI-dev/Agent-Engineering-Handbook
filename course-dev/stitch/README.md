# 用 Stitch 做正式版：怎么分工，怎么下提示词

## 先说结论：精简版之所以薄，是任务下错了，不是 Stitch 不行

Stitch 把提示词里的文字当作「**描述你想要什么设计**」，不当作「**这是要排版的内容**」。
你把一篇 3000 字的课程 md 丢进去说「做个页面」，它会先替你**总结**成七八条要点，
再做一屏很漂亮的卡片墙——UI 很好，内容掉了 80%。这就是「内容量不够」的成因。

「易读性差」是同一件事的后果：内容被压成要点之后，页面上没有长段落，
它就不会给你衬线体、710px 行长、1.85 行高这些**为长文准备的**排版决策。

所以正式版要改的不是审美，是**任务边界**：

| 谁做 | 做什么 |
| --- | --- |
| **Stitch** | 版式与外观：间距、字号阶梯、区块顺序、控件长相、状态样式 |
| **你 / 代码** | 文字（md 原文，一个字不改）、交互逻辑、术语悬停、通过判定 |

---

## 三件必须做的事

### 1. 每次都附现有页面的截图

`reference/` 里有五张，是本地跑起来的真实页面：

| 文件 | 是什么 | 什么时候附 |
| --- | --- | --- |
| `28-scenario-lab.png` | 文章页 + 最常见的互动实验（桌面 1440px） | **默认都附这张** |
| `28-mobile.png` | 同一页 390px | 做响应式时一起附 |
| `30-classify-lab.png` | 选择判断型实验 | 做 ClassifyLab 时 |
| `05-bespoke-lab.png` | 定制型实验（第 05 课的蓝图搭建） | 做特殊实验时 |
| `00-home.png` | 首页与课程总览 | 改导航／目录时 |

**附图比写一百行风格描述管用。**文字契约（`00-style-contract.md`）是补充和硬约束，不是替代。

### 2. 一次只做一课，而且要分段

一课 3000–5000 字，超出 Stitch 一次能认真处理的量——超了它就开始总结。
按 `10-article-page.md` 里的「区块清单」拆成 4–5 次对话：课头 → 正文段落组 → 代码块 →
提示框／误区卡／要点卡 → 拼版。

### 3. 明确写「文字是成品，只排版不改写」

这一条是解决内容变薄的**关键句**，`10-article-page.md` 的模板第一段就在做这件事：

> 下面〈正文〉里的每一个字都是最终稿。你的工作是排版，不是写作：
> 不许改写、精简、总结、换措辞；不许省略任何一句；排不下就调版式，不许删字。

## 目录里有什么

```
00-style-contract.md   风格契约（每条提示词开头都粘这段），已含真实色值与版心
10-article-page.md     文章页模板 + 一课怎么拆成几次对话 + 产出怎么回到仓库
20-lab-states.md       互动实验模板：为什么只能要「状态图」，三种骨架各要几张
30-figure.md           配图：为什么 37 张里大部分该走 SVG 而不是 Stitch
reference/             五张现有页面截图，直接拖进 Stitch
out/                   68 份**已经填好、可以直接粘**的提示词（37 配图 + 31 互动）
```

`out/` 由脚本从课程正文自动编译，规格的来源始终是 `content/lessons/*.md` 里的区块本身：

```bash
python3 course-dev/scripts/build-stitch-prompts.py
```

改完课程正文重跑一次即可。

## 一课的完整流程

1. 打开 `out/U{{课号}}-1.md`，**整段复制**（契约已经拼在里面了）。
2. 新建 Stitch 对话，粘进去，拖入 `reference/28-scenario-lab.png`，发送。
3. 拿到状态图之后追问一次：「给我 390px 版本」。
4. 满意了就导出代码，但**只取版式决策**（间距、字号、层次），
   改进 `apps/web/src/app/globals.css` 里 `.kit-*` 那几十行——**31 课一次全生效**。
5. 文章页同理，用 `10-article-page.md` 的模板，改的是 `.chapter`、`.lesson-article` 那几组。
6. 每改一轮跑一次：`pnpm lint && pnpm build`，再用 Playwright 在 1440px 和 390px
   各看一眼，确认横向溢出是 0px。

## 三个会踩的坑

**不要把 Stitch 导出的 HTML 整页搬进仓库。**它出的是 Tailwind，本站是原生 CSS 变量；
更重要的是，正文里的术语悬停由 `auto-term.tsx` 在 React 树上自动标注，
换成裸 HTML 会把 31 课的术语提示全部弄丢。

**不要让 Stitch 改 `lab-kit.tsx` 的 DOM 结构。**31 课的实验共用那套类名，
Playwright 的验证脚本也按类名找元素。确实需要新节点就单独提出来，统一加。

**不要指望 Stitch 画配图。**37 张配图里 35 张的规格都写死了必须出现的中文标注，
而图像模型画中文几乎必错。默认路线是让能写代码的模型直接产出 SVG——
`out/F*.md` 里的「路线 A」就是为此准备的，颜色直接用站点的 CSS 变量，
改一个字不用重画，还能进 git diff。
